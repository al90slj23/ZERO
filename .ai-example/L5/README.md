# L5 — 操作日志

**定位**：AI 任务完成记录、变更日志、调试过程、会话摘要（黑匣子）。

## 核心原则

- **Append-only** — 只追加，不修改，不删除
- **AI 自动生成** — 任务完成后自动写入
- **终极价值** — 如果 L0-L4 全部丢失，可以从 L5 日志逐步蒸馏重建全部层级

## 目录结构

```
.ai/L5/
├── README.md
├── {YYYY}/
│   └── {MM}/
│       └── {YYYY-MM-DD}.{type}-{topic}.md
└── summaries/
```

## 日志类型

| 类型 | 说明 | 示例文件名 |
|------|------|-----------|
| `task` | 任务完成记录 | `2026-04-16.task-zero-architecture-upgrade.md` |
| `debug` | 调试过程记录 | `2026-04-16.debug-api-timeout.md` |
| `decision` | 架构决策记录 | `2026-04-16.decision-seven-layer-architecture.md` |
| `session` | 会话摘要 | `2026-04-16.session-refactor-review.md` |

## 日志格式

每个日志文件应包含：

```markdown
# {任务标题}

**日期**：{YYYY-MM-DD}
**类型**：{task/debug/decision/session}
**状态**：{completed/in-progress/blocked}

## 任务描述

{简要描述任务目标}

## 变更清单

- 文件1：变更内容
- 文件2：变更内容

## 关键决策

- 决策1：理由
- 决策2：理由

## 遇到的问题

- 问题1：解决方案
- 问题2：解决方案

## 相关规范

- L4: {相关完整规范文件}
- L3: {相关精炼规范文件}
```

## 何时写入

- 任务完成后（通过 hook 自动触发）
- 重大架构决策后（手动记录）
- 复杂调试过程后（手动记录）
- 长会话结束后（手动摘要）

## 重建路径

如果 L0-L4 全部丢失，可以从 L5 日志重建：

```
L5（原始日志）
  → 提取规律和规则 → L4（重建完整规范）
    → 提取要点 → L3（重建精炼规范）
      → 提取分类索引 → L2（重建分类索引）
        → 提取核心 → L1（重建概览）
          → 生成索引 → L0（重建进度）
```

## 访问方式

- 正常情况 AI 不读
- 回溯历史时才读
- 通过文件系统直接访问
