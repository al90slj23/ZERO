## 📍 文档定位

本文档定义 **ZERO 框架的核心表 - 页面清单表（manifest_list）**。

**架构地位**：
- **ZERO 框架的配置中枢**：所有应用 ZERO 框架的项目都应该有这张表
- **单一数据源（Single Source of Truth）**：路由、菜单、权限的唯一配置来源
- **不仅限于 admin**：适用于所有需要路径管理的场景（admin/home/space/api 等）
- **坚固的路径基地**：为整个应用提供一致的路径映射和配置管理

**关联文档**：
- `01.arch-02.structure` - 路径映射规范
- `05.biz-01.menu` - 侧边栏菜单规范
- `02.backend-01.api` - API 路由规范

## 🎯 核心理念

### 单一数据源（Single Source of Truth）

**manifest_list 是整个应用的配置中枢**：

```
文件系统（Vue 页面）→ 数据库（manifest_list）→ 前端渲染（菜单/路由/页面）
     ↓                      ↓                           ↓
  开发时创建            artisan sync                动态加载配置
```

**三大核心功能**：
1. **菜单系统数据源** - 左侧导航菜单的完整树形结构
2. **路由配置中心** - 前端动态路由的生成依据
3. **页面元数据管理** - 页面标题、描述、权限等配置

### 表命名

```
{系统前缀}_manifest_list
```

**命名规则**：
- 系统前缀：项目/模块的标识符
- `manifest`：固定词，表示清单/配置
- `list`：通用语义后缀（单数形式）

**举例**：
- `yys_manifest_list` - 饮阅笙·元愈坊系统核心
- `admin_manifest_list` - 管理后台
- `app_manifest_list` - 应用主体
- `api_manifest_list` - API 路由清单

## 📋 字段设计（基于 YYSYYF 实践）

### 字段分类与排序原则

**按查看/修改频率排序**（规范 02.backend-03.db-fields）：
1. **核心标识字段**（高频查看）- id, path, parent_path
2. **展示信息字段**（高频查看）- name, short_name, icon, description
3. **路由配置字段**（中频修改）- component, redirect, is_external
4. **菜单控制字段**（中频修改）- sort_order, is_visible, is_menu
5. **扩展配置字段**（低频查看）- view_settings, source, file_path
6. **审计字段**（低频查看）- created_at, updated_at, deleted_at

### 1. 核心标识字段（高频查看）

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `id` | BIGINT UNSIGNED | ✅ | 主键，自增 |
| `path` | VARCHAR(255) | ✅ | 页面路径（唯一主体），如 `/admin/yys/manifest/lists` |
| `parent_path` | VARCHAR(255) | ❌ | 父级路径，用于构建菜单树，NULL 表示顶级 |

**设计要点**：
- `path` 必须唯一，带唯一索引
- `path` 必须与文件系统路径一致
- `parent_path` 用于构建树形菜单结构

### 2. 展示信息字段（高频查看）

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `name` | VARCHAR(100) | ✅ | 页面完整名称，如"视图配置管理" |
| `short_name` | VARCHAR(50) | ❌ | 菜单显示名称，如"视图配置"（优先级高于 name） |
| `icon` | VARCHAR(100) | ❌ | 图标名称，如"view-list"（必须验证存在） |
| `description` | TEXT | ❌ | 页面功能描述，用于帮助文档、搜索索引 |

**命名优先级**：
```javascript
// ✅ 简单二元规则
const menuName = item.short_name || item.name

// ❌ 禁止多级降级（掩盖配置问题）
const menuName = item.short_name || item.name || item.title || folderName
```

### 3. 路由配置字段（中频修改）

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `component` | VARCHAR(255) | ❌ | Vue 组件路径，相对于 `resources/js/` |
| `redirect` | VARCHAR(255) | ❌ | 重定向目标路径（用于目录节点） |
| `is_external` | TINYINT(1) | ❌ | 是否外部链接，默认 0 |

**举例**：
```sql
-- 实际页面
path = '/admin/yys/manifest/lists'
component = 'views/admin/yys/manifest/lists/index.vue'

-- 目录节点（无实际页面）
path = '/admin/yys'
redirect = '/admin/yys/manifest/lists'
component = NULL
```

### 4. 菜单控制字段（中频修改）

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `sort_order` | INT | ✅ | 排序权重，数值越小越靠前，默认 1 |
| `is_visible` | TINYINT(1) | ✅ | 菜单可见性，1=显示 0=隐藏，默认 1 |
| `is_menu` | TINYINT(1) | ✅ | 是否作为菜单项，1=菜单 0=仅路由，默认 1 |

**使用场景**：
- `is_visible=0`：隐藏菜单但路由可访问（如详情页）
- `is_menu=0`：仅作为路由，不显示在菜单（如 API 端点）
- `sort_order`：控制同级菜单的显示顺序

### 5. 扩展配置字段（低频查看）

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `view_settings` | JSON | ❌ | 页面级配置对象（见下方详解） |
| `source` | ENUM | ❌ | 数据来源：`database`/`filesystem` |
| `file_path` | VARCHAR(500) | ❌ | 文件系统完整路径，用于同步验证 |

**view_settings 结构**：
```json
{
  "requiresAuth": true,           // 是否需要登录
  "keepAlive": false,             // 是否缓存组件
  "layout": "default",            // 布局模板
  "permissions": ["admin.view"],  // 权限要求
  "meta": {                       // 路由元信息
    "title": "页面标题",
    "breadcrumb": ["首页", "系统", "视图"]
  }
}
```

### 6. 审计字段（低频查看）

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `created_at` | TIMESTAMP | ✅ | 创建时间，默认 CURRENT_TIMESTAMP |
| `updated_at` | TIMESTAMP | ✅ | 更新时间，自动更新 |
| `deleted_at` | TIMESTAMP | ❌ | 软删除时间戳（Laravel 软删除） |

## 🗄️ 完整建表 SQL

```sql
CREATE TABLE `{prefix}_manifest_list` (
  -- 1. 核心标识字段（高频查看）
  `id` bigint unsigned NOT NULL AUTO_INCREMENT 
    COMMENT '1|核心标识|主键ID|自增主键|0',
  `path` varchar(255) NOT NULL 
    COMMENT '2|核心标识|页面路径|唯一路径标识，如 /admin/yys/manifest/lists|1',
  `parent_path` varchar(255) DEFAULT NULL 
    COMMENT '3|核心标识|父级路径|用于构建菜单树，NULL 表示顶级|1',
  
  -- 2. 展示信息字段（高频查看）
  `name` varchar(100) NOT NULL 
    COMMENT '4|展示信息|完整名称|页面完整名称，如"视图配置管理"|1',
  `short_name` varchar(50) DEFAULT NULL 
    COMMENT '5|展示信息|简短名称|菜单显示名称，优先级高于 name|1',
  `icon` varchar(100) DEFAULT NULL 
    COMMENT '6|展示信息|图标名称|TDesign 图标名，如"view-list"|1',
  `description` text 
    COMMENT '7|展示信息|功能描述|页面功能说明，用于帮助文档|0',
  
  -- 3. 路由配置字段（中频修改）
  `component` varchar(255) DEFAULT NULL 
    COMMENT '8|路由配置|组件路径|Vue 组件路径，相对于 resources/js/|1',
  `redirect` varchar(255) DEFAULT NULL 
    COMMENT '9|路由配置|重定向路径|目录节点的重定向目标|0',
  `is_external` tinyint(1) DEFAULT '0' 
    COMMENT '10|路由配置|外部链接|1=外部链接 0=内部路由|0',
  
  -- 4. 菜单控制字段（中频修改）
  `sort_order` int NOT NULL DEFAULT '1' 
    COMMENT '11|菜单控制|排序权重|数值越小越靠前|1',
  `is_visible` tinyint(1) NOT NULL DEFAULT '1' 
    COMMENT '12|菜单控制|菜单可见|1=显示 0=隐藏|1',
  `is_menu` tinyint(1) NOT NULL DEFAULT '1' 
    COMMENT '13|菜单控制|菜单项|1=菜单项 0=仅路由|1',
  
  -- 5. 扩展配置字段（低频查看）
  `view_settings` json DEFAULT NULL 
    COMMENT '14|扩展配置|页面配置|JSON 格式的页面级配置|0',
  `source` enum('database','filesystem') DEFAULT 'database' 
    COMMENT '15|扩展配置|数据来源|database=手动创建 filesystem=自动同步|0',
  `file_path` varchar(500) DEFAULT NULL 
    COMMENT '16|扩展配置|文件路径|文件系统完整路径，用于同步验证|0',
  
  -- 6. 审计字段（低频查看）
  `created_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP 
    COMMENT '17|审计信息|创建时间|记录创建时间|0',
  `updated_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP 
    COMMENT '18|审计信息|更新时间|记录更新时间|0',
  `deleted_at` timestamp NULL DEFAULT NULL 
    COMMENT '19|审计信息|删除时间|软删除时间戳|0',
  
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_path` (`path`),
  KEY `idx_parent_path` (`parent_path`),
  KEY `idx_sort_order` (`sort_order`),
  KEY `idx_is_visible` (`is_visible`),
  KEY `idx_is_menu` (`is_menu`),
  KEY `idx_deleted_at` (`deleted_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci 
  COMMENT='页面清单表|存储所有页面的路由、菜单、权限配置';
```

**索引设计说明**：
- `uk_path`：唯一索引，保证路径唯一性
- `idx_parent_path`：加速树形菜单查询
- `idx_sort_order`：加速排序查询
- `idx_is_visible`, `idx_is_menu`：加速菜单过滤
- `idx_deleted_at`：支持 Laravel 软删除查询

## 🔄 同步机制（零容忍）

### 文件系统 ↔ 数据库同步

**核心原则**：文件系统变化后**必须立即同步**到数据库。

```bash
# 同步命令（Laravel Artisan 示例）
php artisan view:sync       # 扫描文件系统，同步到数据库
php artisan view:validate   # 验证数据库与文件系统一致性
php artisan view:fix        # 自动修复不一致问题
```

### 同步规则

| 文件系统变化 | 数据库操作 | 说明 |
|-------------|-----------|------|
| 新增目录 | INSERT | 插入新记录，`source='filesystem'` |
| 删除目录 | 软删除 | 设置 `deleted_at`，不物理删除 |
| 重命名目录 | UPDATE | 更新 `path` 和 `parent_path` |
| 移动目录 | UPDATE | 更新 `parent_path` |

### 同步流程

```
1. 扫描 resources/js/views/ 目录
2. 提取路径信息：
   - path: /admin/yys/example/demo
   - parent_path: /admin/yys/example
   - component: views/admin/yys/example/demo/index.vue
   - file_path: resources/js/views/admin/yys/example/demo/index.vue

3. 数据库操作：
   - 存在记录 → 更新 file_path, updated_at
   - 不存在 → 插入新记录（source='filesystem'）
   - 文件已删除 → 软删除（deleted_at）

4. 清除缓存（Redis）
   - 清除菜单缓存：menu:full:cached
   - 清除路由缓存：routes:cached
```

### 提交前自检（零容忍）

```bash
# 1. 修改 Vue 文件后
npm run type-check           # TypeScript 检查

# 2. 同步数据库（必须）
php artisan view:sync        # 立即同步

# 3. 验证一致性（必须）
php artisan view:validate    # 提交前验证

# 4. 如有问题自动修复
php artisan view:fix         # 自动修复不一致
```

## 🎯 使用场景与代码示例

### 场景 1：菜单生成（前端）

```javascript
// MenuDataService.ts
import { api } from '@/services/api'

export class MenuDataService {
  /**
   * 获取完整菜单数据（带缓存）
   */
  static async getFullMenuCached() {
    const response = await api.get('/api/v1/admin/yys/viewInfos/lists:fullMenuCached')
    return response.data
  }

  /**
   * 构建树形菜单
   */
  static buildMenuTree(flatData: ManifestItem[]) {
    const tree: MenuItem[] = []
    const map = new Map<string, MenuItem>()

    // 过滤并排序
    const items = flatData
      .filter(item => item.is_visible && item.is_menu)
      .sort((a, b) => a.sort_order - b.sort_order)

    // 构建映射
    items.forEach(item => {
      map.set(item.path, {
        label: item.short_name || item.name,
        icon: item.icon,
        path: item.path,
        children: []
      })
    })

    // 构建树形结构
    items.forEach(item => {
      const node = map.get(item.path)!
      if (item.parent_path && map.has(item.parent_path)) {
        map.get(item.parent_path)!.children.push(node)
      } else {
        tree.push(node)
      }
    })

    return tree
  }
}
```

### 场景 2：动态路由注册（前端）

```javascript
// router/index.ts
import { createRouter, createWebHistory } from 'vue-router'
import { MenuDataService } from '@/services/MenuDataService'

export async function setupRouter() {
  const router = createRouter({
    history: createWebHistory(),
    routes: []
  })

  // 从 manifest_list 获取路由配置
  const manifestData = await MenuDataService.getFullMenuCached()

  // 动态注册路由
  manifestData.forEach(item => {
    if (item.component) {
      router.addRoute({
        path: item.path,
        name: item.path.replace(/\//g, '_'),
        component: () => import(`@/${item.component}`),
        meta: {
          title: item.name,
          requiresAuth: item.view_settings?.requiresAuth ?? true,
          keepAlive: item.view_settings?.keepAlive ?? false,
          permissions: item.view_settings?.permissions ?? []
        }
      })
    }
  })

  return router
}
```

### 场景 3：权限控制（后端）

```php
// app/Http/Middleware/CheckManifestPermission.php
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use App\Models\ManifestList;

class CheckManifestPermission
{
    public function handle(Request $request, Closure $next)
    {
        $path = $request->path();
        
        // 从 manifest_list 获取页面配置
        $manifest = ManifestList::where('path', '/' . $path)->first();
        
        if (!$manifest) {
            abort(404, '页面不存在');
        }
        
        // 检查权限
        $permissions = $manifest->view_settings['permissions'] ?? [];
        
        foreach ($permissions as $permission) {
            if (!$request->user()->hasPermission($permission)) {
                abort(403, '无权访问');
            }
        }
        
        return $next($request);
    }
}
```

### 场景 4：菜单数据获取（后端 API）

```php
// app/Http/Controllers/Api/Admin/Yys/ViewInfosController.php
namespace App\Http\Controllers\Api\Admin\Yys;

use App\Http\Controllers\Controller;
use App\Models\ManifestList;
use Illuminate\Support\Facades\Cache;

class ViewInfosController extends Controller
{
    /**
     * 获取完整菜单（带缓存）
     */
    public function fullMenuCached()
    {
        return Cache::remember('menu:full:cached', 3600, function () {
            return ManifestList::whereNull('deleted_at')
                ->orderBy('sort_order')
                ->get();
        });
    }

    /**
     * 刷新菜单缓存
     */
    public function refreshCache()
    {
        Cache::forget('menu:full:cached');
        Cache::forget('routes:cached');
        
        return response()->json([
            'success' => true,
            'message' => '缓存已刷新'
        ]);
    }
}
```

## 📊 菜单数据获取优先级

```
1. Redis 缓存（key: menu:full:cached）
   ↓ 未命中
2. 数据库查询（manifest_list）
   ↓ 查询成功
3. 构建树形结构（parent_path 关联）
   ↓
4. 写入 Redis 缓存（TTL: 1小时）
   ↓
5. 返回前端
```

**缓存策略**：
- 缓存键：`menu:full:cached`
- TTL：3600 秒（1 小时）
- 失效时机：
  - 执行 `view:sync` 后
  - 手动调用 `refreshCache` API
  - 修改 manifest_list 记录后

## 🚨 常见问题与解决方案

### 问题 1：菜单不显示新页面

**原因**：忘记同步数据库

**解决**：
```bash
php artisan view:sync
php artisan view:validate
```

### 问题 2：修改 short_name 后菜单未更新

**原因**：Redis 缓存未清除

**解决**：
```bash
# 方法 1：清除所有缓存
php artisan cache:clear

# 方法 2：调用刷新 API
POST /api/v1/admin/yys/viewInfos/lists:refreshCache
```

### 问题 3：路由 404 但数据库有记录

**原因**：`component` 字段路径错误

**检查**：
```sql
SELECT id, path, component FROM {prefix}_manifest_list WHERE path = '/admin/xxx';
```

**修正**：
```sql
-- component 必须相对于 resources/js/
UPDATE {prefix}_manifest_list 
SET component = 'views/admin/xxx/index.vue' 
WHERE path = '/admin/xxx';
```

### 问题 4：新建目录后菜单未出现

**原因**：未执行同步命令

**解决流程**：
```bash
# 1. 创建目录和文件
mkdir -p resources/js/views/admin/yys/example/demo
touch resources/js/views/admin/yys/example/demo/index.vue

# 2. 立即同步（零容忍）
php artisan view:sync

# 3. 验证
php artisan view:validate

# 4. 前端自动加载
```

### 问题 5：菜单层级错误

**原因**：`parent_path` 设置错误

**检查**：
```sql

WHERE path LIKE '/admin/yys/%' 
ORDER BY path;
```

**修正**：
```sql

UPDATE {prefix}_manifest_list 
SET parent_path = '/admin/yys'
```

## 📝 实践案例：YYSYYF 项目

**表名**：`yys_manifest_list`

**记录数**：约 150+ 条（覆盖 8 个业务模块）

**关键特性**：
1. **树形菜单**：通过 `parent_path` 构建 3 级菜单
2. **动态路由**：前端路由完全由数据库驱动
3. **权限控制**：`view_settings.permissions` 控制页面访问
4. **缓存优化**：Redis 缓存 + 1 小时 TTL
5. **自动同步**：`view:sync` 命令自动扫描文件系统

**成功经验**：
- 新增页面只需创建 Vue 文件 + 执行 `view:sync`
- 菜单调整只需修改数据库 + 刷新缓存
- 权限变更无需修改代码，只需更新 `view_settings`

## 🎯 设计哲学

1. **Evidence > assumptions** - 证据胜过假设
   - 文件系统是证据，数据库必须与之同步
   
2. **Code > documentation** - 代码胜过文档
   - 数据库表结构即文档，字段注释即说明
   
3. **Simple binary > complex hierarchy** - 简单二元规则胜过复杂多级优先级
   - `short_name || name`，不要多级降级
