# 10.ai-memory-02.naming - AI 记忆体系命名与格式规范

> **文档版本**：v1.0.0
> **创建日期**：2026-07-18
> **定位**：定义 `.ai/` 六层体系的目录命名、文件命名、frontmatter 格式，以最低成本兼容主流 AI 开发工具

---

## 设计约束来源

本规范基于以下工具的实际技术行为制定：

| 工具 | 规则目录 | 加载文件类型 | 解析 frontmatter | 不认识的 frontmatter |
|------|---------|-------------|-----------------|---------------------|
| Claude Code | `.claude/rules/` | `.md` only | ✅ (`paths`) | 忽略 |
| Cursor | `.cursor/rules/` | `.md` `.mdc` | ✅ (`globs` `description` `alwaysApply`) | 忽略 |
| Windsurf | `.windsurf/rules/` | `.md` only | ✅ (`trigger` `globs` `description`) | 忽略 |
| Continue | `.continue/rules/` | `.md` only | ✅ (`name` `globs` `description` `alwaysApply`) | 忽略 |
| Kiro | `.kiro/steering/` | `.md` only | ✅ (`inclusion` `fileMatchPattern` `description`) | 忽略 |
| **Roo Code** | `.roo/rules/` | **所有文件** | ❌ 不解析 | **原文注入 prompt** |
| Codex | `AGENTS.md` only | — | ❌ | **原文注入** |
| GitHub Copilot | `.github/instructions/` | `.instructions.md` | ✅ (`applyTo`) | 忽略 |

**关键发现**：
1. Roo Code 加载目录内**所有文件类型**（含 `.yaml` `.json` `.txt`）→ L2 目录内**只放 `.md`**
2. 大多数工具不认识的 frontmatter 字段会**静默忽略**（安全）
3. Roo Code 和 Codex 会将 frontmatter **原文注入** prompt（浪费 token 但不报错）

## 目录命名规范

### 通用规则

| 规则 | 理由 |
|------|------|
| **不用下划线** | 保持路径整洁 |
| **用连字符 `-` 分词** | 所有工具支持，Kiro 官方推荐 |
| **全小写**（层级目录 L0-L6 除外） | 跨平台安全（macOS 不区分大小写，Linux 区分） |
| **层级目录用大写 `L` + 数字** | 短、清晰、不与业务目录混淆 |
| **不用点号 `.` 开头的子目录** | 避免被 `.gitignore` 规则意外匹配 |

### 各层目录命名

```
.ai/
├── L0/                          ← 大写 L + 数字
├── L1/
├── L2/
├── L3/
│   ├── active/                  ← 全小写连字符（不用 _active）
│   ├── completed/
│   └── backlog/
├── L4/
│   ├── standards/
│   ├── references/
│   ├── adr/
│   └── philosophy/
├── L5/
│   ├── 2026/                    ← 年份
│   │   └── 04/                  ← 月份
│   └── summaries/
├── meta.yaml                    ← 放根目录（不放 L2 内，防 Roo Code 误载）
└── sync.sh
```

### L3 功能目录命名

```
.ai/L3/active/
├── fang-service-layer/          ← 全小写连字符
├── tdesign-mobile-migration/
└── build-optimization/
```

## 文件命名规范

### 默认编号原则

**编号命名是默认规范，全部层级统一使用，无例外。**

工具兼容性差异通过 symlink 解决，不通过命名妥协。

| 层级 | 命名方式 | 示例 |
|------|---------|------|
| L0 | **功能目录** | `specs/active/feature-name/` |
| L1 | **固定名** | `00.overview.md`（唯一文件） |
| L2 | **分类编号** | `00.meta.md` `01.arch.md` `02.backend.md` |
| L3 | **编号** | `02.backend-01.api.md` |
| L3 spec | **编号** | `00.spec-01.requirements.md` |
| L4/standards | **编号**（与 L3 对应） | `02.backend-01.api.md` |
| L4/adr | **ADR 序号** | `0001-database-driven-routing.md` |
| L4/references | **编号** | `05.ref-01.admin-layout.md` |
| L5 日志 | **日期编号** | `2026-04-13.task-01.fang-wallet.md` |

**Kiro 兼容**：Kiro 要求 spec 目录内文件名为 `requirements.md` `design.md` `tasks.md`。通过 sync.sh 创建 symlink 映射，不改变源文件命名：

```
.kiro/specs/{feature}/
├── requirements.md  → symlink → .ai/L3/active/{feature}/00.spec-01.requirements.md
├── design.md        → symlink → .ai/L3/active/{feature}/00.spec-02.design.md
├── tasks.md         → symlink → .ai/L3/active/{feature}/00.spec-03.tasks.md
└── decisions.md     → symlink → .ai/L3/active/{feature}/00.spec-04.decisions.md
```

### L2 编号命名体系（核心）

```
{大类编号}.{类别}-{序号}.{主题}.md
```

**编号段解析**：
```
02.backend-03.db-01.tables.md
│   │        │   │   │
│   │        │   │   └── 子主题名称
│   │        │   └── 子主题序号
│   │        └── 类别内序号
│   └── 类别名称
└── 大类编号
```

**大类编号定义**：

| 编号 | 类别 | 说明 |
|------|------|------|
| 00 | `meta` | 元规范 |
| 01 | `arch` | 架构规范 |
| 02 | `backend` | 后端规范 |
| 03 | `frontend` | 前端规范 |
| 04 | `data` | 数据规范 |
| 05 | `biz` | 业务规范 |
| 06 | `quality` | 质量规范 |
| 07 | `security` | 安全规范 |
| 08 | `ops` | 运维规范 |
| 09 | `tool` | 工具规范 |
| 10 | `ref` | 参考/扩展 |

**命名字符规则**：

| 规则 | 正确 | 错误 |
|------|------|------|
| 全小写 | `02.backend-01.api.md` | `02.Backend-01.API.md` |
| 连字符分词 | `db-tables.md` | `db_tables.md` |
| 纯 `.md` 后缀 | `01.arch-01.core.md` | `01.arch-01.core.mdc` |
| 不含空格/中文 | `api-design.md` | `API 设计.md` |
| 数字段两位 | `02.backend-01` | `2.backend-1` |

### L5 日志命名

```
{YYYY-MM-DD}.{type}-{topic}.md
```

| 类型 | 含义 | 示例 |
|------|------|------|
| `task` | 任务完成记录 | `2026-04-13.task-fang-wallet-refactor.md` |
| `debug` | 调试过程记录 | `2026-04-13.debug-tdesign-datepicker.md` |
| `decision` | 决策变更记录 | `2026-04-14.decision-switch-to-kuzu.md` |
| `session` | 会话摘要 | `2026-04-14.session-memory-arch-design.md` |

## Frontmatter 规范

### 设计目标

用**最少的字段**覆盖**最多的工具**。

### L2 文件 Frontmatter（核心兼容格式）

**始终加载的文件**（无 scope 限定）：

```yaml
---
description: "Core architecture rules that apply to all code"
---
```

**按需加载的文件**（有 scope 限定）：

```yaml
---
description: "Vue component development rules and patterns"
globs: "**/*.vue"
---
```

**只用两个字段**：`description` + `globs`（可选）。

### 各工具对这两个字段的行为

| 工具 | `description` | `globs` | 实际效果 |
|------|---|---|---|
| Cursor | ✅ agent 判断依据 | ✅ 按 glob 触发 | 精准按需加载 |
| Continue | ✅ agent 判断依据 | ✅ 按 glob 触发 | 精准按需加载 |
| Windsurf | ✅ model_decision 依据 | ✅ 按 glob 触发 | 精准按需加载 |
| Kiro | ✅ auto inclusion 依据 | ❌ 忽略（它用 `fileMatchPattern`） | 靠 description 智能匹配 |
| Claude Code | ❌ 忽略（它用 `paths`） | ❌ 忽略 | 无条件加载（可接受） |
| Roo Code | ❌ 原文显示 | ❌ 原文显示 | 浪费 2 行 token（无害） |

**无 globs 时的各工具行为**：
- Cursor/Continue：默认始终加载 ✅
- Windsurf：默认 always_on ✅
- Kiro：默认 always ✅
- Claude Code：无条件加载 ✅
- Roo Code：加载所有文件 ✅

### 不使用的字段

| 字段 | 不用的原因 |
|------|-----------|
| `trigger` | Windsurf 专属 |
| `paths` | Claude Code 专属 |
| `fileMatchPattern` | Kiro 专属 |
| `applyTo` | GitHub Copilot 专属 |
| `alwaysApply` | 不写此字段 = 默认行为已满足需求 |
| `inclusion` | Kiro 专属 |

### L1/L3/L4/L5 文件 Frontmatter

L1/L3/L4/L5 的文件**不通过工具 rules 目录加载**（不是 symlink 目标），因此不需要兼容多工具的 frontmatter。

可自由使用项目特定的 frontmatter：

```yaml
---
title: 规范标题
created: 2026-07-18
updated: 2026-07-18
---
```

## meta.yaml 规范

`meta.yaml` 放在 `.ai/` 根目录，供 `sync.sh` 同步脚本读取，不供 AI 工具读取。

### 用途

为需要特殊处理的工具提供 frontmatter 翻译信息（初期可不实现）。

```yaml
# .ai/meta.yaml
version: "1.0.0"

# L2 模块的工具特定 scope 翻译
# sync.sh 在为特定工具生成文件时，用这里的信息替换 globs
modules:
  - file: "03.frontend-01.vue.md"
    translations:
      claude-paths: ["resources/js/**/*.vue"]
      kiro-fileMatchPattern: ["**/*.vue", "**/*.tsx"]
      copilot-applyTo: "**/*.vue,**/*.tsx"

  - file: "02.backend-01.api.md"
    translations:
      claude-paths: ["app/Http/**", "routes/**"]
```

**初期策略**：通用 frontmatter（`description` + `globs`）已覆盖 80%+ 场景。`meta.yaml` 翻译是进阶优化，可后续按需实现。

## sync.sh 同步脚本规范

### 职责

1. **建立 symlink**：将各工具的 rules 目录链接到 `.ai/L2/`
2. **生成入口文件**：从 L0+L1 生成 `AGENTS.md`、`CLAUDE.md` 等
3. **验证链接完整性**：检查所有 symlink 是否正常
4. **格式翻译**（进阶）：为特定工具生成翻译后的文件

### 工具目录映射表

| 工具 | 目标目录 | 链接方式 |
|------|---------|---------|
| Claude Code | `.claude/rules/` | symlink → `.ai/L2/` |
| Cursor | `.cursor/rules/` | symlink → `.ai/L2/` |
| Continue | `.continue/rules/` | symlink → `.ai/L2/` |
| Kiro | `.kiro/steering/` | symlink → `.ai/L2/` |
| Windsurf | `.windsurf/rules/` | symlink → `.ai/L2/` |
| Trae | `.trae/rules/` | symlink → `.ai/L2/` |
| Roo Code | `.roo/rules/` | symlink → `.ai/L2/` |

### 入口文件生成规则

| 入口文件 | 来源 | 生成逻辑 |
|----------|------|---------|
| `AGENTS.md` | L0 + L1 精华 | 通用格式，英文，≤300 行 |
| `CLAUDE.md` | L0 + L1 完整 | 可含中文，Claude 特定指令，≤600 行 |
| `GEMINI.md` | L0 + L1 精华 | 按需生成 |
| `.github/copilot-instructions.md` | L1 精华 | 按需生成 |

### gogogo.sh 集成

在项目的 `gogogo.sh` 中新增选项：

```bash
./gogogo.sh ai        # AI 记忆体系管理
./gogogo.sh 8f        # 映射所有工具（快捷）
./gogogo.sh 8g        # 移除所有映射（快捷）
```

子菜单（`./gogogo.sh ai`）：
```
1. 初始化/重建所有链接（L1+L2+L3）
2. 检查 AI 体系状态
3. 同步 Kiro specs（L0→.kiro/specs/）
4. 写入 L5 操作日志
0. 返回
```

## 禁止清单

| ❌ 禁止 | 替代方案 |
|---------|---------|
| `.ai/` 内出现 `CLAUDE.md` `AGENTS.md` | 由 sync.sh 在项目根生成 |
| `.ai/L2/` 内放 `.yaml` `.json` `.txt` | `meta.yaml` 放 `.ai/` 根 |
| 目录名用下划线 `_active` | 用 `active` |
| 文件名用下划线 `tech_stack` | 用 `tech-stack` |
| 文件名用大写（L0-L6 目录名除外） | 全小写 |
| 文件名含空格或中文 | 全英文连字符 |
| 使用 `.mdc` 格式 | 统一用 `.md` |
| 在 L2 文件中使用工具专属 frontmatter 字段 | 只用 `description` + `globs` |
| 手动维护各工具 rules 目录的内容 | 通过 symlink 自动同步 |

## 从旧体系迁移

### 映射关系

| 旧位置 | 新位置 | 层级 |
|--------|--------|------|
| `AGENTS.md` | `AGENTS.md`（sync.sh 生成） | L0 导出 |
| `CLAUDE.md` | `CLAUDE.md`（sync.sh 生成） | L0+L1 导出 |
| `.claude/memories/*.md` | `.ai/L2/*.md` | L2 |
| `.claude/memories/README.md` | `.ai/L1/index.md` | L1 |
| `.ai/L4/standards/*.md` | `.ai/L4/standards/` | L4 |
| `.kiro/specs/*/` | `.ai/L0/specs/active/` 或 `completed/` | L0 |
| `.ai/L4/philosophy/` | `.ai/L4/philosophy/` | L4 |

### 迁移步骤

```
Phase 1: mkdir -p .ai/{L0,L1,L2,L3,L4/{standards,references,adr,philosophy},L5,L6}
Phase 2: mv .claude/memories/*.md → .ai/L2/（保留编号命名）
Phase 3: mv old-standards/ → .ai/L4/standards/
Phase 4: 从 AGENTS.md/CLAUDE.md 蒸馏出 L1 文件
Phase 5: 创建 L0 项目进度管理目录
Phase 6: 运行 sync.sh 建立 symlink
Phase 7: 验证各工具正常读取
Phase 8: 清理旧目录中的重复文件
```
