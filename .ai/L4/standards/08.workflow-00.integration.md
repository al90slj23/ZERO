> **创建日期**：2026-04-12
> **版本**：v1.0.0
> **目标**：将 ZERO 框架和 ALD 规范集成到 AI 开发工作流

## 🎯 核心概念

### 三层规范体系

```
第 1 层：ZERO 框架规范（通用基础）
  ├── 核心架构原则
  ├── 路径映射规则
  ├── API 设计规范
  ├── 数据库规范
  └── ...

第 2 层：项目特定规范（如 ALD）
  ├── Go 编码模式
  ├── Channel 集成
  ├── Relay 架构
  ├── UI 规范
  └── AI 协作规范

第 3 层：工作流规范（平台特定）
  ├── Cursor IDE 工作流
  ├── Kiro 工作流
  ├── Claude Code CLI 工作流
  └── OpenCode 工作流
```

### 规范与日志的闭环

```
查看规范
    ↓
根据规范编码
    ↓
记录工作日志
    ↓
回顾日志
    ↓
改进规范
    ↓
（循环）
```

## 🚀 快速开始

### 步骤 1：选择开发平台

根据你的需要选择：

| 平台 | 推荐指数 | 最适合 | 文档 |
|------|--------|--------|------|
| Cursor | ⭐⭐⭐⭐⭐ | 快速开发和原型 | workflow-01 |
| Kiro | ⭐⭐⭐⭐⭐ | 深度思考和设计 | workflow-02 |
| Claude Code CLI | ⭐⭐⭐⭐ | 自动化和 CI/CD | workflow-03 |
| OpenCode | ⭐⭐⭐⭐ | 定制工作流 | workflow-04 |

### 步骤 2：配置环境

参考对应的工作流规范文档进行配置。

### 步骤 3：加载规范

在你的项目中：
```bash
# 复制规范文件
cp -r ZERO/rules/ your-project/
cp -r ZERO/.ai/L5/ your-project/

# 配置 IDE
# (具体步骤见工作流规范)
```

### 步骤 4：开始开发

在开发中：
1. 使用快捷键查询规范（如 Cmd+K）
2. 参考规范进行编码
3. 完成功能后记录工作日志
4. 定期回顾和改进

## 💡 主要特性

### 1. 规范快速查询

**在 Cursor 中**
```
Cmd + K → "@rules 如何设计 API？"
↓
立即获得相关规范
```

**在 Kiro 中**
```
左侧面板 → Rules
↓
搜索功能名称
↓
自动显示相关规范
```

### 2. 工作日志自动化

**记录日志**
```
Cmd + K → "创建今天的工作日志"
↓
自动生成文件名
↓
插入标准模板
↓
根据提交自动填充内容
```

**周总结**
```
Cmd + K → "生成本周的周总结"
↓
汇总所有日志
↓
生成综合总结
```

### 3. 规范自动应用

**代码补全**
```
Tab 补全会自动参考规范
→ 遵循命名规范
→ 遵循架构规范
→ 遵循错误处理规范
```

**代码审查**
```
Cmd + K → "审查这段代码"
↓
自动应用规范检查
↓
提供改进建议
```

## 🔄 工作流整合示例

### 场景：实现新的 API 端点

```
1. 查看规范（5 分钟）
   ↓
   Cmd + K → "@rules API 设计规范"
   ↓
   阅读 02.backend-01.api.md

2. 设计 API（20 分钟）
   ↓
   按照规范设计
   ↓
   应用检查清单

3. 实现代码（30 分钟）
   ↓
   参考 Go 编码规范
   ↓
   使用 Tab 补全（自动应用规范）

4. 审查代码（10 分钟）
   ↓
   Cmd + K → "审查这段代码"
   ↓
   应用改进建议

5. 记录日志（10 分钟）
   ↓
   创建 2026-04-13-new-api.md
   ↓
   记录完成情况、学到的东西

6. 提交代码（5 分钟）
   ↓
   git add . && git commit
   ↓
   完成！
```

**总耗时**：80 分钟

与没有工作流规范的比较：
- 无规范：120+ 分钟（包括反复改进）
- 有规范：80 分钟（一次通过）

**效率提升**：33%
