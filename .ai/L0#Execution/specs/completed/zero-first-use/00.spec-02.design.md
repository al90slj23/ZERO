# 首次引入设计

状态：completed；日期：2026-10-23。

## 两个阶段

1. `zero-bootstrap.sh --target <项目> --prepare-only`：预检、备份、合并明确模板、保留原规则、生成项目事实入口和首次适配待办，设置一次性客户端连接。
2. Agent 核验项目技术栈/现有约束，归位知识，分析代码/路由/权限/数据库与 ZERO 的差异，完成安全可验证的改造和必要的兼容计划；再运行同入口的完整模式。

完整模式调用 `retrieval-indexes.sh init`：本地安装锁定 CLI，下载模型，在 `.ai` 中建立 QMD 文档索引和 CodeGraph 源码图。运行准备完成与项目适配完成单独记录，不相互代替。

## 存储

脚本、配置源与 toolchain lock 位于 L0；现有资料只合并不覆盖。备份位于目标 L0/backups，避免将旧备份递归归档。运行态工具/模型/数据库位于 L5/.generated。Codex 配置源在 L0/configs，根 `.codex/config.toml` 为相对软链，保留原有 TOML 选项与其他 MCP。

普通 QMD 读取不刷新全库；MCP 启动后台补齐，任务收尾互斥完整刷新。CodeGraph 准备阶段加锁，长期共享 daemon 不持准备锁。
