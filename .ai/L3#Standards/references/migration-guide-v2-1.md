# ZERO v2.1：L5 与检索适配迁移

> **更新日期**：2026-10-23
> **适用范围**：采用 ZERO 的项目；按项目逐个迁移
> **当前规范**：[检索与关联适配规范](../standards/10.ai-memory-04.retrieval-adapters.md)

## 名称与能力

L5 正式名称由“知识图谱”调整为 **L5#知识检索与关联 (Knowledge)**，物理路径仍为 `.ai/L5#Knowledge/`。L5 是工具化查询层，默认适配 QMD 文档检索与 CodeGraph 源码关系图。通用实体、事件、时间图可按明确需求扩展，不能把这两个工具的组合直接当成完整实现。

## 既有 L5 内容归位

先盘点原有 Markdown、图数据库或其他知识服务并保留可恢复副本；不能为了清空 L5 删除仍然唯一保存的事实。按资料的实际用途选择目标：

| 既有资料 | 目标 |
|----------|------|
| 项目身份、关键边界的简要说明 | L1；详细资料链接到 L3 |
| 当前开发规则 | L3/standards |
| 当前宿主合同、领域事实、能力目录、拓扑与操作参考 | L3/references 或 L3/guides，保留来源与验证日期 |
| 进行中的任务、迁移状态和验收清单 | L0/specs/active |
| 历史决策、部署结果、排障与审计记录 | 有日期的 L4 日志 |
| 生成的向量、符号节点、关系边、检索缓存 | `.ai/L5#Knowledge/.generated/`，可从原始资料重建 |

迁移时保留原文、来源、日期和 Git 历史，更新所有入口、代码、脚本与文档引用。确有兼容需要时可暂留旧路径的转向说明，标记迁移目标与移除条件；禁止两边继续写入。确认引用与内容完整后，L5 仅保留接入说明。旧 L4 日志反映当时状态，不改写其历史叙述。

如果已有真正的图数据库：先确认其中是否存在没有原始证据的唯一事实；导出并归位后再重建派生图。QMD/CodeGraph 不负责自动迁移第三方图数据库。

## 接入与自动刷新

首次引入优先按 [首次引入指南](zero-first-use.md) 使用 bootstrap：先备份/准备，再由 Agent 归位资料并适配项目，最后完整初始化。以下说明用于核对迁移后的依赖与边界。

1. 把所需的 `.ai` 规范和本地工作流合并进目标项目，保留项目自己的入口和边界。`retrieval-indexes.sh` 与同目录 `retrieval-lock.py` 一并复制；macOS/Linux 使用 Python 3 标准库文件锁。
2. 合并 L5 的 `.gitignore`，使 `.generated/` 不参与提交；在现有根 `.gitignore` 忽略自动入口 `/.codegraph`。所有配置、数据库、模型缓存放在 `.ai` 内。检查 Node.js 22+、npm 和 Python 3.11+；完整初始化会按 L0 toolchain 在 `.ai` 内安装两个 CLI。
3. 接入 Agent 从目标项目根目录执行，日常不交由用户重复维护：

```bash
bash .ai/L0#Execution/workflows/local/retrieval-indexes.sh refresh
bash .ai/L0#Execution/workflows/local/retrieval-indexes.sh status
```

4. 客户端分别用适配器的 `qmd-mcp` / `codegraph-mcp` 启动，工作目录设为该项目根目录。所需策略保存在 `.ai`，客户端保留连接入口。
5. 项目入口要求 Agent 在修改 `.ai` 后于任务收尾执行 `retrieval-indexes.sh refresh`；也可用项目已有的任务结束 hook 触发同一命令。CodeGraph 在活动 MCP 会话中自行监听源码。

适配器使用 `.ai/L5#Knowledge/.generated/` 下的命名索引，不读取旧根 `.qmd` 配置。旧 QMD 如有其他唯一集合配置，接入 Agent 先盘点并迁移其策略来源，再停用旧入口；不盲目删除旧资料。新配置由适配器生成，项目搬迁时自动更新路径并保留模型缓存。

已有根 `.codegraph` 实体目录时，适配器会在目标无冲突时保留原数据并移入 `.ai`，随后建立软链；两边已存在或链接目标不同则停止，由接入 Agent 核对。CodeGraph 的目录限制决定根 `.codegraph` 入口暂不可省，但它没有第二份数据。检索适配器只按 L0 锁定版本安装本地 CLI，不执行会重写指令的 CodeGraph installer；bootstrap 以保留原文的受管区块补充入口。

默认使用标准共享 daemon 支持多个对话；工具自行维护用户目录进程登记和临时 socket，项目知识与索引仍全部在 `.ai`。QMD 启动后台补齐，普通读取不刷库，任务收尾等待完整刷新。

## 迁移验收

- 原有 L5 事实仍能从归位后的源文件找到，原引用已更新或有临时转向。
- 当前规范、读取流程、蒸馏流程和命名表使用新的 L5 定义。
- QMD 命中当前项目新修改的 `.ai` 内容；CodeGraph 反映已同步的源码变化。
- 删除索引不会丢失唯一事实；重新初始化可恢复检索能力。

本指南是逐项目迁移步骤。更新 ZERO 模板本身不等于其他项目的事实资料已迁移，也不等于其 MCP 已连通。
