# 08.workflow-00 工作流规范整合

> **当前规范**：`.ai/L3#Standards/standards/08.workflow-00.integration.md`

> **⚠️ 注意**：本文档描述 **IDE 开发工作流规范**（如何使用 Cursor、Kiro 等 IDE 进行开发）。
>
> 如需配置 **CI/CD 自动化流程**（GitHub Actions、GitLab CI 等），请参考 `.ai/L0#Execution/workflows/`。

## 三层规范体系

```
第 1 层：ZERO 框架规范（通用基础）
  ├── 核心架构原则
  ├── 路径映射规则
  ├── API/数据库规范
  └── ...

第 2 层：项目特定规范
  ├── 技术栈规范
  ├── 业务规范
  └── ...

第 3 层：工作流规范（平台特定）
  ├── Cursor IDE 工作流
  ├── Kiro 工作流
  ├── Claude Code CLI 工作流
  └── OpenCode 工作流
```

## 快速开始

### 1. 选择开发平台

| 平台 | 推荐指数 | 最适合 | 文档 |
|------|--------|--------|------|
| Cursor | ⭐⭐⭐⭐⭐ | 快速开发和原型 | 08.workflow-01 |
| Kiro | ⭐⭐⭐⭐⭐ | 深度思考和设计 | 08.workflow-02 |
| Claude Code CLI | ⭐⭐⭐⭐ | 自动化和 CI/CD | 08.workflow-03 |
| OpenCode | ⭐⭐⭐⭐ | 定制工作流 | 08.workflow-04 |

### 2. 配置环境

新项目和首次采用 ZERO 的已有项目统一按 [首次接入指南](../references/zero-first-use.md) 初始化，保留已有项目规则、知识与客户端设置。本版 bootstrap 使用 `--client codex` 自动配置 Codex 连接；其他客户端按其当前设置接入 `.ai` 中的指令源与 QMD / CodeGraph 启动入口。

`gogogo.sh 8*` 仅管理已有结构的旧 IDE 映射，不承担首次接入。项目技术栈与组件库由项目自己的规范决定。

### 3. 规范快速查询

**在 Cursor 中**
```
Cmd + K → "@rules 如何设计 API？"
```

**在 Kiro 中**
```
左侧面板 → Rules → 搜索功能名称
```

## 主要特性

### 1. 规范自动应用
- Tab 补全自动参考规范
- 代码审查自动应用规范检查

### 2. 工作日志自动化
- 自动生成日志文件名
- 插入标准模板
- 根据提交自动填充内容

### 3. 规范与日志闭环
```
查看规范 → 编码 → 记录日志 → 回顾 → 改进规范 → (循环)
```
