## 🚀 初始化 Cursor 项目

### 第 1 步：首次采用 ZERO

新项目与已有项目按 [首次接入指南](../references/zero-first-use.md) 建立或合并 `.ai`，保留已有项目规则、知识与客户端设置。`gogogo.sh 8*` 只处理既有映射，不承担首次接入。

### 第 2 步：引用项目规范

在当前 Cursor 支持的项目指令入口引用 `.ai/L1#Overview/guide.md`，经 `.ai/L2#Index/toc.md` 定位所需 L3 规范。项目规则和 Prompt 的唯一源保存在 `.ai`，客户端仅保留其支持的入口或映射。

语言、框架和组件库由项目规范决定。需要 Go 编码、Channel 或 Relay 专门约定时，由项目自行定义并登记到 L2；ZERO 不提供这些预设标准文件。

### 第 3 步：接入检索

本版 bootstrap 的 `--client codex` 自动配置 Codex。Cursor 需按其当前 MCP 设置合并连接，分别调用 `.ai/L0#Execution/workflows/local/retrieval-indexes.sh qmd-mcp` 与 `codegraph-mcp`，工作目录为目标项目根目录。本文不规定 Cursor 配置文件格式或模型选择。

## 💻 Cursor 工作流

### 开发前的准备（5 分钟）

```
1. 打开项目
   Command + Shift + P → "Cursor: Open Folder"

2. 查看规范索引
   打开 .ai/L2#Index/toc.md，定位当前任务相关规范

3. 选择相关规范
   根据任务类型，打开对应的规范文件
```

### 开发中的使用（持续）

#### 使用 Cmd+K 快速查询规范

```
Cmd + K → 输入查询

示例：
"@rules 如何命名变量？" → 返回命名规范
"@rules API" → 查找 API 规范
"@rules 项目技术栈" → 查找项目已选语言与框架约定
```

#### 在 Tab 补全时应用规范

Cursor 的 Tab 补全会自动参考：
- 打开的规范文件
- `.cursor/rules/` 中的 Prompt
- 项目的命名和架构风格

**最佳实践**
```
边开发边参考规范：
1. 分屏打开规范文件和代码文件
2. 在代码编辑时，Tab 补全会学习规范的风格
3. 遇到疑问，Cmd+K 快速查询
```

#### 代码审查时使用 Cursor

```bash
# 1. 选中代码
# 2. 使用 Cmd+K 提问
Cmd + K → "按照规范审查这段代码"

# Cursor 会参考规范文件进行审查
```

## 🔍 快速查询的最佳方式

### 方式 1：使用 `@rules` 符号

```
Cmd + K → "@rules"

然后输入关键词：
- "@rules 命名" → 所有命名相关规范
- "@rules 项目技术栈" → 已选语言与框架规范
- "@rules 数据库" → 数据库相关规范
```

### 方式 2：直接引用规范文件

```
Cmd + K → "在 `.ai/L3#Standards/standards/02.backend-01.api.md`
和项目已选技术栈的基础上，完成以下接口..."

Cursor 会自动读取规范文件并应用
```

### 方式 3：使用分屏显示

```
1. 左侧：规范文件（按 Cmd+\ 分屏）
2. 右侧：代码文件
3. 边参考规范边编码
```

## 📝 Cursor 中的工作日志集成

### 在 Cursor 中记录日志

#### 方式 1：直接创建文件

```bash
# 1. 打开项目文件浏览器
打开 .ai/L4#Changelog/，按该层 README 的约定记录历史

# 2. 新建文件
Cmd + N → 命名为 2026-04-13-feature-name.md

# 3. 使用 Cmd+K 生成模板
Cmd + K → "根据 .ai/L4#Changelog/README.md，记录已完成内容、验证和剩余事项"

# 4. 填写内容
# 5. 保存并提交
```

#### 方式 2：使用快捷命令

在 `.ai` 中维护快捷 Prompt，并通过当前客户端支持的入口引用：

```markdown
## 快速创建工作日志

使用此命令：
Cmd + K → "创建今天的工作日志"

Cursor 会：
1. 自动生成日期文件名
2. 插入标准模板
3. 根据今天的提交自动填充内容
```

### 日志的持续记录

**每小时**（15 分钟）
```
快速保存当前进度：
- 完成的小功能
- 遇到的问题
- 临时解决方案
```

**每天下班前**（10 分钟）
```
Cmd + K → "生成今天的每日总结"

Cursor 会汇总：
- 所有完成的功能
- 遇到的问题和解决方案
- 学到的东西
- 明天的计划
```

**每周末**（30 分钟）
```
Cmd + K → "生成本周的周总结"

Cursor 会综合：
- 本周所有的日志
- 关键成果和经验
- 问题分析和改进建议
- 下周计划
```

## ⚙️ Cursor 的高级配置

### 1. 自定义 Tab 补全风格

项目编码规则维护在 L3，并登记到 L2；在当前 Cursor 支持的规则入口引用其源文件。以下是 Prompt 内容示例，不是客户端配置格式：

```markdown
# Cursor Tab 补全风格指南

## 后端代码

遵循项目已经选定的语言和框架约定，以及 ZERO 的命名和 API 规范。

### 函数命名
- 完整描述 > 缩写
- 具体大小写遵循当前语言和项目命名约定

### 错误处理
- 遵循项目当前错误处理规范
- 以测试和实际运行行为验证错误分支

## 前端代码

遵循项目当前选定的前端框架、组件库和界面规范。

### 组件
- 延续项目已经确认的组件模式与类型约定
- 接入 ZERO 不自动更换前端技术栈或组件库
```

### 2. 项目级的 AI Prompt

在 `.ai` 中维护项目 Prompt，通过当前 Cursor 支持的入口引用：

```markdown
# Cursor 系统 Prompt

你是当前项目的 AI 开发助手。

## 核心原则

1. 遵循 ZERO 框架规范
2. 参考当前项目的技术栈、业务边界和自有规范
3. 记录工作日志
4. 提供检查清单

## 规范引用

当用户请求代码时，自动：
1. 查看相关的规范文档
2. 在代码中应用规范要求
3. 提供检查清单
4. 建议记录工作日志

## 工作流

每个开发任务的标准流程：
1. 查看相关规范
2. 生成代码
3. 应用检查清单
4. 提示记录日志
```

## 🎯 典型的 Cursor 工作流

### 场景 1：实现新的接口

```
1. 打开规范
   打开 .ai/L2#Index/toc.md，定位 API 与项目技术栈规范

2. 描述任务
   Cmd + K → "实现一个处理用户注册的函数，
   按照规范中的模式"

3. 生成代码
   Cursor 会生成符合规范的代码

4. 应用检查清单
   Cmd + K → "应用检查清单"

5. 记录日志
   新建日志文件，记录完成情况
```

### 场景 2：代码审查

```
1. 选中代码
2. Cmd + K → "按照规范审查这段代码"
3. Cursor 会：
   - 对比规范
   - 指出不符合之处
   - 提供改进建议
4. 应用改进
5. 记录学到的东西
```

### 场景 3：调试问题

```
1. 描述问题
   Cmd + K → "这个错误的原因是什么？"

2. Cursor 会：
   - 查看规范中的错误处理部分
   - 参考项目的最佳实践
   - 提供解决方案

3. 在工作日志中记录：
   - 问题的原因
   - 解决方案
   - 为什么这样解决
   - 下次如何避免
```

## 💡 最佳实践

### 1. 分屏开发

```
左侧：规范文件（不变）
右侧：代码文件（编辑）
底部：终端

这样可以在参考规范的同时编码
```

### 2. 使用快捷键

```
Cmd + K：查询规范或生成代码
Cmd + \：分屏
Cmd + E：打开资源管理器
Cmd + /：打开终端
```

### 3. 每小时保存日志

```
定时保存当前进度：
- 完成的代码
- 待解决的问题
- 学到的东西

这有助于最后写周总结
```

### 4. 参考相关规范

```
不要记住所有规范，而是学会：
- 用 .ai/L2#Index/toc.md 快速查询
- 用 @rules 快速搜索
- 用分屏参考相关规范
```
