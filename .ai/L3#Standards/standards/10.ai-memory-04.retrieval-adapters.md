# 10.ai-memory-04 检索与关联适配规范

> **版本**：v2.1.2
> **更新日期**：2026-10-23
> **适用层**：L5#知识检索与关联 (Knowledge)

## 单一维护源

项目只维护 `.ai` 内的知识源资料。L0-L4 保存执行资料、项目入口、规范与历史；L5 提供工具化查询能力。QMD 配置、索引、模型缓存和 CodeGraph 图数据库都由适配器在 `.ai` 内构建，无需手工维护第二套内容。源码仍位于原模块，运行行为和外部系统状态以其实际证据核验。

| 来源 | 默认工具 | 能力 | 边界 |
|------|----------|------|------|
| `.ai` 原始文档 | QMD | 全文、语义、混合检索 | 文本相似度不等于实体关系，也不能裁决规范版本 |
| 项目源码 | CodeGraph | 符号、引用、调用、继承和影响面探索 | 代码关系不等于通用业务事实图，静态分析不能证明运行时行为 |

两者没有自动融合成一张通用实体/事件/时间图。确有该类查询需求时再接入专用适配器，仍须自动从原始证据构建并带来源、时间、更新/删除和重建规则，不能增加人工双写要求。

## 权威性与读取

1. 先读当前任务的 L0 规格和 L1 入口，经 L2 定位 L3 当前规范；项目有具体读取顺序时遵循项目入口。
2. 已有精确路径/符号就定向读相关范围；未知文档主题先用 QMD，调用、依赖和影响面等源码关系问题用小范围 CodeGraph。
3. 结果要能追溯到来源路径和相关段落/行号。工具返回的当前源码视为已读，复用当前对话仍可见的未变片段；只补缺失或过期范围。发现冲突或关键行为问题时仍须核对拥有该事实的源文件/系统。
4. L4 是当时的历史，不能覆盖后续 L3 当前规范。检索排名不决定权威性。
5. 新事实只写回其所属源资料。禁止手改索引、把检索输出直接升级为规范、在 L5 维护知识正文。

## 查询预算与复用

1. **先判断是否已知位置**：已知文档、文件或符号时直接读所需范围，不依次经过 QMD、CodeGraph 和全仓搜索来重新定位。已知标准文件先在该文件内定位标题或锚点，再读所属段落；任务不需要全文时，不从第 1 行猜一个宽泛上界。只有关系问题才需要用已知符号发起图查询。
2. **文档从小结果 lex 起步**：限定 `zero-ai` 集合，一条 `lex` 子查询，提供具体 `intent`，通常 `limit: 3`、不超过 5，并设置 `rerank: false`。词汇不匹配时先有针对性地改词；概念召回不足才用 vec，未知词汇或复杂召回需要时才启用自动扩展。不是每次查询都先运行 status。
3. **源码关系从小范围起步**：CodeGraph 使用具体符号/路径，通常 `maxFiles: 3`。已返回的当前源码不再整文件重读；只在缺少控制流上下文、出现过期提示或需要核验图外事实时补读范围。图已给出调用者路径但没返回正文时，直接读调用者代码块，不再查询同一 helper 而重复带回其全文。
4. **限制读取与打印**：QMD `get` 通常取命中附近 40–80 行，`multi_get` 只选必要文件并设置逐文件行数。源码读取覆盖所属函数/代码块及必要上下文；需要时逐步扩大。输出保留所选路径、行号及证据片段，不把整个工具对象和其中正文重复打印。
5. **复用同一事实**：同一对话中已读、仍可见且未变的片段直接复用，不重复搜同义词或重开相同文件。补充定位信息留在当前任务/对话，不建立另一套手工片段库或知识源。
6. **保留完整性例外**：首次必读项目上下文、审计、整文件逻辑/不变量检查、用户明确要求全文及未解决的跨文件行为，可以扩大或通读；这些预算不削弱拥有者证据、项目规则或充分验证。
7. **有限重试与降级**：检索不可用最多一次针对性重试，然后在可能的所属目录用 `rg` 和范围读取。空结果不等于索引坏了，不以广搜循环或强制刷新代替改进定位。

## `.ai` 内的存储与映射

```text
.ai/
├── L0#Execution/workflows/local/
│   ├── retrieval-indexes.sh                         # 唯一适配入口
│   ├── retrieval-lock.py                            # 标准库互斥助手
│   └── retrieval-state.py                           # 源内容与成功状态核对
└── L5#Knowledge/
    ├── README.md / .gitignore                       # 本层说明与忽略规则
    └── .generated/                                 # 自动生成，不提交
        ├── qmd/config/zero.yml                     # 自动集合配置
        ├── cache/qmd/zero.sqlite                   # QMD 数据库
        ├── cache/qmd/models/                       # QMD 模型缓存
        └── codegraph/                              # CodeGraph 数据库等
.codegraph -> .ai/L5#Knowledge/.generated/codegraph   # 工具入口指针，无第二份内容
```

QMD 由适配器设置 `QMD_CONFIG_DIR`、`XDG_CACHE_HOME` 并使用命名 index `zero`，避免误用父目录或全局索引。不要直接运行会在项目根创建 `.qmd` 的 `qmd init`。

CodeGraph 当前 `CODEGRAPH_DIR` 只接受根目录内的单段名称，因此适配器自动生成 `.codegraph` 软链，将实际数据保存在 `.ai`。不要设置 `CODEGRAPH_DIR=.ai`，否则工具会把整个知识目录当成其可删除数据目录。默认不需要根 `codegraph.json`；以后确需配置时也应从 `.ai` 内唯一源映射。

CodeGraph 1.6.2 已在 macOS 真实验证软链建图、CLI 查询、MCP 读取和 watcher 同步；这是版本实测兼容，官方未承诺所有未来版本/平台。默认采用标准共享 daemon，多个 AI 对话共用同一项目图。项目知识与索引在 `.ai`，自动进程登记（`~/.codegraph`）和临时 socket 属于工具运行状态，无需人工维护。

`.generated/` 通过本层 `.gitignore` 排除；索引输入仅为原始 Markdown 与源码，生成物不能被当成新知识。QMD 的 `zero-ai` 集合另外明确忽略 `L0#Execution/backups/**` 和 `**/.generated/**`，避免备份重复文本进入检索；`L0#Execution/evidence/` 中的原始证据仍属于可检索源资料。Git 忽略和集合忽略各自负责提交范围与检索范围。

生成配置归适配器所有，不手工优化；需要修改策略时改 L0 适配入口。准备索引时会比对当前生成配置的模型、源路径、集合 pattern 和 ignore 与适配器策略；旧配置缺字段、内容漂移或旧 YAML 需要规范化时，在 QMD 锁内重建配置并更新文本库。只有嵌入模型未知或变更才要求强制重嵌入，单纯修正排除策略不会主动清空已有向量或重拉模型。

## 运行路径保护与旧库迁移

预检在安装、加锁及打开数据库前检查 `.ai` 和生成态的所属目录，拒绝异常目录别名、软链和特殊文件。npm `.bin` 链接仅在其目标为本项目真实 `node_modules` 内的普通文件时允许。共享 daemon 的 `.ai/L5#Knowledge/.generated/codegraph/daemon.sock` 是唯一特殊文件例外：必须是当前用户拥有的 Unix socket；其他位置的 socket、其他特殊文件及软链仍拒绝，预检不停止已有 daemon。

根 `.codegraph` 软链必须精确指向相对目标 `.ai/L5#Knowledge/.generated/codegraph`。旧的真实根目录只在目标库不存在时迁入；存在其他链接目标或两份库时停止并报告冲突，不覆盖或自行合并。迁移原始知识仍须先备份、保留逐项映射和引用，路径保护不替代内容无损验证。

标准库锁助手校验父目录，并用 `O_NOFOLLOW` 打开持久锁文件，拒绝最终路径上的软链；维护子进程继承锁描述符。工具安装、QMD 刷新和 CodeGraph 准备分别串行化，长期 MCP 服务不持有准备锁。

## 自动构建与更新

使用 [本地适配器](../../L0%23Execution/workflows/local/retrieval-indexes.sh) 作为 QMD 与 CodeGraph 的统一启动入口：

```bash
# Agent 完成项目适配后显式初始化三个模型与两类索引
bash .ai/L0#Execution/workflows/local/retrieval-indexes.sh init
# Agent 批量完成源资料修改后收尾执行一次；只读任务不主动刷新
bash .ai/L0#Execution/workflows/local/retrieval-indexes.sh refresh
# 客户端分别以这两个命令启动 MCP，cwd 必须为目标项目根目录
bash .ai/L0#Execution/workflows/local/retrieval-indexes.sh qmd-mcp
bash .ai/L0#Execution/workflows/local/retrieval-indexes.sh codegraph-mcp
# 普通读取使用现有索引，不触发全库扫描
bash .ai/L0#Execution/workflows/local/retrieval-indexes.sh qmd search '命名规则' -c zero-ai -n 3
bash .ai/L0#Execution/workflows/local/retrieval-indexes.sh status
# 仅在确认索引异常时强制修复；会重建向量并执行图初始化/同步
bash .ai/L0#Execution/workflows/local/retrieval-indexes.sh refresh-force
```

QMD MCP 启动先准备源集合和文本库，随后在后台检查是否需要补齐索引，使用现有索引提供服务；启动日志在 `.generated/qmd/` 内。Agent 批量完成 `.ai` 源文档写入后在任务收尾运行一次 `refresh`，等待需要的刷新结束；只读任务和源资料未变不主动刷新。将验收记录等源文档一并写完再收尾，生成态变化不再触发新一轮源文档/刷新循环。普通读取不触发全库扫描，也不清查询缓存。QMD 本身没有文件 watcher；默认触发来自 MCP 启动与 AGENTS/L1 收尾调用。

本版没有安装或注册原生 Codex Stop hook。L0 的 Kiro `askAgent` 模板只适用于对应客户端，不能作为 Codex 可执行 hook。以后若加入非 managed 原生 Codex hook，需要按正式客户端机制对具体定义另行信任；放置文件或信任项目不等于该 hook 已激活。

macOS/Linux 使用 Python 3 标准库文件锁串行化配置构建和完整刷新，不依赖 `ps` 检查；多个启动入口复用正在运行的刷新，不重复建嵌入。首次或变更文档嵌入尚未完成时，语义结果可能滞后，使用 QMD status 核对待处理数量。完整嵌入不设默认 30 分钟截断。

CodeGraph 的入口创建、旧库迁移和就绪判断使用标准库锁串行化。暖数据库及活动共享 daemon 有效时复用 watcher，不在每次 MCP 连接时重复 `init`/`sync`；没有活动 daemon 时，源内容指纹一致才复用，否则初始化并同步离线变化。长期 MCP 服务不持有准备锁，继续由共享 daemon 协调。索引失败时保留源资料，Agent 有限重试或降级并报告状态，不能假称已更新。

QMD `update` 会刷新当前 index 的全部集合；适配器只生成本项目 `zero-ai` 集合，不设置会改动工作树的 pull/update hook。默认固定 Qwen3-Embedding-0.6B Q8，并保持建索引/查询模型一致；旧模型库切换时重嵌入。首次下载/建图由接入 Agent 通过完整初始化完成。

### 成功状态复用与显式修复

`retrieval-state.py` 在刷新锁内比较源文档内容、生成配置、适配器/助手/已安装工具状态和模型清单摘要。QMD 只有 `.generated/qmd/refresh-success.json` 与当前指纹一致，且真实 SQLite 中 `zero-ai` 活跃文档路径/hash 与源集合完全匹配、每个 hash 都有当前模型及格式指纹所需的完整 chunk 时才跳过 `update`/`embed`。CLI 退出 0 本身不等于索引完整。普通查询不执行这套全源/覆盖检查，也不重新读取大模型计算 SHA。

CodeGraph 的 `.generated/codegraph-prepared.json` 绑定数据库 device/inode、必要 schema/index 元数据、固定工具版本和适配实现。活动 daemon 复用还须通过同用户精确 socket、daemon/writer 的同 PID、writer ready/mode、daemon 版本/socket 路径及进程存活检查。没有可复用 daemon 时比较 Git 可见且未忽略的源树内容 hash；非 Git 项目按排除规则遍历源树。离线内容有变就执行 `init`/`sync`。复用 watcher 不取消查询时的源新鲜度提示及必要核验。

升级时若尚无匹配的成功记录，但实际数据库与当前用户的共享 daemon 已健康就绪，可在相同版本/socket/PID/稳定源码检查后直接接管并建立新记录；不为创建记录而重复 init/sync。显式 init 与 refresh-force 不采用该捷径。

两条维护路径都会比较处理前后的源指纹。处理中有并行源变更时最多进行三轮稳定检查；仍在变化、覆盖不完整或命令失败时返回失败，不写成功标记。等待同一锁的调用方只复用已核验的成功结果。

`refresh-force` 显式绕过复用，执行 QMD `update`、`embed -f` 和 CodeGraph `init`/`sync`，仍遵守相同锁和稳定性检查。它可能开销较大，只用于已诊断的索引陈旧/损坏，不作为空结果重试或只读任务的常规步骤。显式 `init` 仍准备三个模型并强制图初始化/同步，适用于首次接入。

## 安装与客户端边界

首次接入遵循 [首次引入指南](../references/zero-first-use.md)。`zero-bootstrap.sh` 先备份、合并知识源和一次性连接，Agent 完成项目适配后执行完整初始化。普通项目不得以模板替换现有事实、路由、表和部署脚本。

工具版本由 `L0#Execution/configs/retrieval-toolchain/package.json` 和 lockfile 固定，v2.1.2 不改变工具与模型选择。`retrieval-indexes.sh setup` 幂等安装本项目 `.ai` 内 CLI；安装指纹包含源 manifest/lockfile 与 Node 版本、模块 ABI、平台和架构，并核对实际包版本，匹配时复用。`init` 还会预拉全部三个模型并完成 QMD/CodeGraph 初次索引，`refresh` 自动补缺失工具并按需刷新。无需全局安装。工具安装、模型下载或索引失败均不得声称接入完成；源资料继续可直接读取。

完整初始化成功拉取模型后，在 `.generated/qmd/models-manifest.json` 记录实际文件大小与 SHA256。以后完整初始化先校验三个模型，校验通过即复用缓存；文件缺失或变更时重新调用官方拉取。HF ETag 不等同于原始文件 SHA256。普通读取、MCP 启动和日常刷新不执行这个完整模型校验或预下载步骤。

本版 bootstrap 自动合并 Codex 项目 TOML，将配置源放在 `.ai`、根入口设为相对软链；保留其他设置和 MCP。已有同名配置冲突先报错，不覆盖。其他客户端按各自正式格式引用适配器，不能把文件复制等同于工具已连接。

CodeGraph `install` 会修改 `AGENTS.md` 等指令文件，可能触及 ZERO 的 L1 映射。bootstrap 负责受控合并，不调用该 installer；可用 `codegraph install --print-config <agent>` 查看模板。适配器设置 `CODEGRAPH_TELEMETRY=0` 和 `DO_NOT_TRACK=1`，不修改全局偏好。

官方 `uninit` 遇到数据目录软链只删除入口，保留 `.ai` 中的目标；重置前应停止相关进程并明确处理派生数据目标。

## 验收与成本

- 源资料新增、修改、删除后，自动刷新应反映变化；QMD 命中本项目文档，CodeGraph 反映已同步源码。
- QMD 排除备份/生成物而保留原始 evidence；旧生成配置缺少 ignore 或发生策略漂移后能够恢复。
- 多对话使用时核验两个 CodeGraph MCP 客户端共享项目 daemon，一方退出后另一方仍可查询；合法同用户指定 socket 不阻止后续初始化/刷新。
- `.ai` 内包含全部项目知识源、配置与生成数据；根 `.codegraph` 仅为软链。
- 删除生成索引不丢失唯一事实，适配器能重建。旧 L5 文档先按 [迁移指南](../references/migration-guide-v2-1.md) 归位。
- 运行时验收与首次项目适配分别记录；索引可用不能替代业务边界、命名、接口及数据约定的审计与实际改造。
- 用同类任务、相同问题范围及所需证据比较查询/读取次数、返回内容量、重复未变片段、刷新实际工作和答案正确性；将执行耗时与模型计费分开记录。更短的调用轨迹本身不能证明费用下降，结果须实测，不预设固定节省比例。
- 以命中质量、处理 Token、驻留上下文和耗时测量收益，不保证固定节省比例。
