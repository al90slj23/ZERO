# 08.workflow-00 - 工作流规范元文档

> **文档版本**：v1.0.0
> **创建日期**：2026-04-12
> **适用范围**：所有 AI 开发平台和工具
> **目标**：将 ZERO 框架和项目自有规范集成到日常开发工作流

---

## 📋 文档定位

本文档定义 **如何在不同的 AI 开发平台上应用 ZERO 框架和项目自有规范**，包括：

- 规范体系的快速集成指南
- 各个平台的工作流最佳实践
- 规范文档在工作流中的位置
- 工作日志的自动化记录
- 平台特定的优化建议

---

## 🎯 核心概念

### 规范体系的三个层次

```
第 1 层：ZERO 框架规范（通用）
  ├── 核心架构原则
  ├── 路径映射规则
  ├── 数据库规范
  └── 前端规范
         ↓
第 2 层：项目自有规范（项目特定）
  ├── 已选语言与框架
  ├── 业务与宿主边界
  ├── 模块集成约定
  └── 已选组件库
         ↓
第 3 层：工作流规范（平台特定）
  ├── Cursor 工作流
  ├── Kiro 工作流
  ├── Claude Code CLI 工作流
  └── OpenCode 工作流
```

### 规范的应用流程

```
新项目启动
    ↓
1. 选择 AI 开发平台
    ↓
2. 加载平台特定的工作流规范
    ↓
3. 集成 ZERO 框架规范
    ↓
4. 合并项目自有规范，保留现有技术栈和业务边界
    ↓
5. 配置工作日志记录
    ↓
开始开发
```

## 🔗 与其他规范的关系

### ZERO 框架规范（通用基础）
- **适用于**：所有项目
- **内容**：架构、路径、API、数据库等
- **位置**：`.ai/L3#Standards/standards/01-06.*.md`
- **优先级**：P1, P2, P3

### 项目自有规范（项目特定）
- **适用于**：采用 ZERO 的当前项目
- **内容**：该项目已选的语言、框架、业务边界与集成约定
- **位置**：沿用项目当前的 L3 结构，在 L2 登记实际文件
- **引用方式**：引用已存在的项目规范。Go 编码、Channel 或 Relay 等专门规则须由需要它们的项目自行定义，ZERO 不预设这些技术栈或对应文件。

### 工作流规范（平台特定）- 本文档
- **适用于**：特定的 AI 开发平台
- **内容**：工作流、配置、集成方式
- **位置**：`.ai/L3#Standards/standards/08.workflow-*.md`
- **新增概念**：平台集成、自动化、优化

### 日志规范（过程记录）
- **位置**：[L0 执行说明](../../L0%23Execution/README.md) 与 [L4 历史说明](../../L4%23Changelog/README.md)
- **与工作流的关系**：工作流的输出
- **整合方式**：实施进度与验证写入所属 L0 规格，架构决定和历史回执写入 L4

### 应用到新项目的步骤

新项目与已有项目首次采用 ZERO，统一按 [首次接入指南](../references/zero-first-use.md) 处理。bootstrap 将目标项目的知识、指令与检索策略放入 `.ai`，合并已有内容并建立可追溯备份；项目入口须描述目标项目本身。

本版使用 `--client codex` 自动配置 Codex 连接。其他客户端按其实际支持的设置，引用 `.ai` 指令源和适配器的 `qmd-mcp` / `codegraph-mcp` 入口，工作目录为目标项目根目录。旧 `gogogo.sh 8*` 仅管理既有映射，不能代替首次接入。

## 🔄 工作流与规范的交互

### 典型的开发流程

```
1. 开始新功能
   ↓
2. 查看相关的规范文档
   （从 .ai/L2#Index/toc.md 快速查询）
   ↓
3. 根据规范编写代码
   ↓
4. 定期记录工作日志
   ↓
5. 完成功能
   ↓
6. 最后提交日志总结
```

### 规范文档的访问方式

**在 Cursor 中**
```
快捷键：Cmd+K （打开命令面板）
引用：.ai/L2#Index/toc.md （快速查询）
```

**在 Kiro 中**
```
左侧面板：点击 Rules 标签
搜索：输入功能名称
快速查询表：自动显示相关规范
```

**在命令行中**
```bash
cat .ai/L2#Index/toc.md
rg -n "当前任务的关键词" .ai/L3#Standards/
```

## 💡 规范与工作日志的整合

### 工作日志中如何引用规范

```markdown
# YYYY-MM-DD - 实现新的 API

> **相关规范**：`.ai/L3#Standards/standards/02.backend-01.api.md`

## 完成内容

- 按照当前 API 规范实现了接口
- 遵循了项目已经选定的语言与框架规范
- 完成了错误处理的检查清单
```

### 工作日志推动规范改进

```
开发过程
    ↓
遇到规范不清楚的地方
    ↓
在工作日志中记录疑问
    ↓
定期审查工作日志
    ↓
改进相关的规范文档
    ↓
更新 ZERO 框架
```

## 🎯 推荐的学习路径

### 第 1 天：快速入门

```
1. 读本文档（15 分钟）
2. 选择工作流规范（5 分钟）
3. 配置 IDE（30 分钟）
4. 读 P1 规范（38 分钟）
   → 现在可以开始编码了！
```

### 第 1 周：建立习惯

```
每天：
- 在开始新任务时查规范（5 分钟）
- 编写代码（大部分时间）
- 完成时记录日志（10 分钟）

周末：
- 回顾本周的工作日志
- 总结学到的东西
- 识别规范需要改进的地方
```

### 第 1 个月：掌握完整体系

```
- 深入学习 P2 和 P3 规范
- 参与规范的改进和优化
- 建立个人的最佳实践文档
- 与团队分享经验
```
