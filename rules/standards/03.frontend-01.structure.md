# 03.frontend-01.structure - 文件命名规范

> **文档版本**：v1.0.0
> **创建日期**：2025-12-30

---

## 📍 文档定位

本文档定义**文件命名规范**，包括点分命名法和文件大小限制。

---

## 🎯 核心理念

1. **点分命名**：用点号区分文件类型（`.view.`、`.logic.`、`.style.`）
2. **职责分离**：视图、逻辑、样式分离
3. **文件大小控制**：单文件适中，便于维护

---

## 📋 点分命名规范

### 命名格式

```
FeatureName.FileType.ext
```

| 类型 | 后缀 | 举例 |
|------|------|------|
| 视图 | `.view.html` | `UsersList.view.html` |
| 逻辑 | `.logic.js` | `UsersList.logic.js` |
| 样式 | `.style.css` | `UsersList.style.css` |
| API | `.api.php` | `UsersList.api.php` |
| 配置 | `.config.js` | `UsersList.config.js` |
| 类型 | `.types.ts` | `UsersList.types.ts` |

### FeatureName 生成规则

**核心公式**：**FeatureName = 路径最后两级目录名组合（大驼峰）**

| 目录路径 | FeatureName |
|----------|-------------|
| `/admin/users/list/` | `UsersList` |
| `/admin/orders/config/` | `OrdersConfig` |

### 子功能拆分

当功能复杂时，可按子功能拆分：

```
UsersList/
├── index.html
├── UsersList.view.html
├── UsersList.logic.js
├── UsersList.style.css
│
│   # 子功能
├── UsersList.Create.view.html
├── UsersList.Create.logic.js
├── UsersList.Edit.view.html
├── UsersList.Edit.logic.js
├── UsersList.BatchUpload.view.html
└── UsersList.BatchUpload.logic.js
```

## 🏷️ 层级标识规范

当同一目录下存在多种类型的文件（页面入口组件、功能模块组件、共享资源等），需要使用**层级标识**来明确文件归属。

### 命名格式（扩展）

```
FeatureName.{ModuleName|Scope|Shared|index}.{ComponentName|FileType}.ext
```

### 三种层级标识 + 一个临时标识

| 标识 | 用途 | 可见范围 | 使用场景 |
|------|------|---------|---------|
| `ModuleName` | 功能模块 | 模块内部 | 明确属于某个功能模块的组件 |
| `Scope` | 作用域资源 | 仅当前层级 | 只服务于当前层级的所有组件和资源 |
| `Shared` | 共享资源 | 同级及子级 | 可以被兄弟层级或子层级复用和调用 |
| `index` | 临时归属 | - | 暂时不确定归属时使用（后续应调整） |

### 核心理念

**正常情况下只有 3 种**：
1. **ModuleName** - 明确属于某个功能模块
2. **Scope** - 只服务于当前层级（包括页面组件、独立功能、私有工具）
3. **Shared** - 可以被兄弟或子层级复用

**`index` 只作为"暂时不确定"的临时归属**，后续应调整为 `Scope` 或 `Shared`。

### 决策流程

```
创建新文件
    ↓
是否明确属于某个功能模块？
    ├─ 是 → 使用 ModuleName（如 Monitor、Logs、Settings）
    │
    └─ 否 → 是否需要被兄弟或子层级调用？
            ├─ 是 → 使用 Shared
            │
            ├─ 否 → 使用 Scope
            │
            └─ 不确定 → 暂时使用 index（后续调整）
```

### 使用示例

```
pages/admin/sam/
├── index.vue                                    # 页面入口
│
├── 作用域组件（Scope）
│   ├── AdminSam.Scope.Header.vue                # 页面头部
│   ├── AdminSam.Scope.Tabs.vue                  # 标签页导航
│   ├── AdminSam.Scope.CurrentAuth.vue           # 当前认证信息
│   ├── AdminSam.Scope.AccountBar.vue            # 账户信息栏
│   └── AdminSam.Scope.helpers.ts                # 私有工具函数
│
├── 功能模块（ModuleName）
│   ├── AdminSam.Monitor.vue                     # SAM 监控模块
│   ├── AdminSam.Monitor.logic.ts                # 监控逻辑
│   ├── AdminSam.Logs.vue                        # 保活日志模块
│   └── AdminSam.Logs.logic.ts                   # 日志逻辑
│
└── 共享资源（Shared）
    ├── AdminSam.Shared.api.ts                   # 所有模块都可以用
    ├── AdminSam.Shared.types.ts                 # 可以被兄弟或子层级调用
    └── AdminSam.Shared.utils.ts                 # 可以被复用
```

### 层级标识对比

| 特性 | ModuleName | Scope | Shared | index |
|------|-----------|-------|--------|-------|
| **可见范围** | 模块内部 | 当前层级 | 同级及子级 | 临时 |
| **是否可被兄弟调用** | ❌ | ❌ | ✅ | - |
| **是否可被子级调用** | ❌ | ❌ | ✅ | - |
| **是否可被父级调用** | ❌ | ❌ | ❌ | - |
| **典型用途** | 功能模块 | 页面组件、独立功能、私有工具 | 共享资源 | 暂时不确定 |
| **示例** | Monitor、Logs | Header、CurrentAuth、helpers.ts | api.ts、types.ts | TempComponent.vue |

### 注意事项

1. **`Scope` 的广泛性**：所有只服务于当前层级的组件和资源都用 `Scope`，包括：
   - 页面组件（Header、Tabs）
   - 独立功能组件（CurrentAuth、AccountBar）
   - 私有工具函数（helpers.ts、validators.ts）

2. **`index` 只是临时标识**：不确定归属时使用，后续应该调整为 `Scope` 或 `Shared`

3. **依赖方向**：依赖应该向上（子依赖父），不应该向下（父依赖子）

4. **避免过度设计**：大部分情况下只需要 `ModuleName`、`Scope` 和 `Shared`

## � 文件职范责定义

### 入口文件 - index.html / index.php

**职责**：功能的统一访问入口

**行数限制**：20-50行

### 视图文件 - FeatureName.view.*

**职责**：页面模板结构

**行数限制**：200-800行

### 逻辑文件 - FeatureName.logic.js

**职责**：业务逻辑、状态管理、API调用

**行数限制**：200-800行

### 样式文件 - FeatureName.style.css

**职责**：CSS样式

**行数限制**：200-1000行

---

## 📏 文件大小规范

| 文件类型 | 推荐 | 上限 | 强制重构 |
|---------|------|------|---------|
| 入口文件 | 20-50 | 80 | >100 |
| 视图文件 | 200-450 | 650 | >800 |
| 逻辑文件 | 200-400 | 600 | >800 |
| 样式文件 | 200-400 | 600 | >1000 |
| 函数/方法 | 10-40 | 80 | >120 |

### 超限处理

当文件超过上限时：
1. **视图文件**：拆分为子组件
2. **逻辑文件**：拆分为子模块或工具函数
3. **样式文件**：按功能区域拆分

---

## 🐘 后端类文件特殊规范

**PHP/Java 类文件禁止点分命名**，必须使用纯驼峰：

```php
// ❌ 错误：PHP 文件不能使用点分命名
UsersList.Controller.php

// ✅ 正确：使用纯驼峰
UsersListController.php
```

**原因**：PHP/Java 命名空间语法不支持点号

## 🔁 重构规范

### 绝对禁止修改的内容

- ❌ 变量名称
- ❌ API接口（URL、参数、响应字段）
- ❌ 业务逻辑
- ❌ 函数名称

### 重构必须保证

- ✅ 100%功能完整性
- ✅ 100%接口一致性
- ✅ 100%逻辑一致性
