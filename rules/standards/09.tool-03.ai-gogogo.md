# 09.tool-03.ai-gogogo - AI 记忆体系管理入口规范

> **文档版本**：v2.0.0
> **更新日期**：2026-04-15
> **定位**：定义 `gogogo.sh ai` 和 `gogogo.sh 8` 作为 AI 记忆体系统一入口的职责边界、脚本结构和操作规范

---

## 核心结论

**AI 记忆体系属于内容体系，维护它的入口属于 ZERO 工具体系。**

1. `.ai/` 目录只放 AI 记忆内容本身，不放运维脚本
2. 所有初始化、映射、重建、验证操作，都通过 `gogogo.sh` 入口完成
3. 用户只记 `./gogogo.sh ...`，不记内部实现路径

---

## 两个入口

### `gogogo.sh 8` — 映射管理（`gogogo.8.sh`）

管理 `.ai/` 各层到各 IDE/CLI 工具的符号链接映射。

```bash
./gogogo.sh 8     # 交互式菜单
./gogogo.sh 8f    # 建立所有映射（最常用）
./gogogo.sh 8g    # 移除所有映射（并检查非链接文件）
./gogogo.sh 8a    # 仅映射 Kiro
./gogogo.sh 8b    # 仅映射 Cursor
./gogogo.sh 8c    # 仅映射 Claude Code
./gogogo.sh 8d    # 仅映射 Windsurf
./gogogo.sh 8e    # 仅映射 Continue
```

### `gogogo.sh ai` — AI 体系管理（`gogogo.ai.sh`）

管理 AI 记忆体系的状态、Kiro specs 同步、L5 日志写入。

```bash
./gogogo.sh ai    # 交互式菜单
```

## 映射规范（`gogogo.8.sh`）

### 映射层级

| 层级 | 源 | 目标 | 说明 |
|------|-----|------|------|
| L1 | `.ai/L1/00.overview.md` | `AGENTS.md`, `CLAUDE.md`, `.cursorrules`, `.windsurfrules` | 单文件链接 |
| L2 | `.ai/L2/*.md`（排除 README.md） | `.kiro/steering/`, `.cursor/rules/`, `.claude/memories/`, `.continue/rules/`, `.windsurf/rules/` | 逐文件链接 |
| L0 | `.ai/L0/specs/{active,backlog,completed}` | `.kiro/specs/`, `.cursor/specs/`, `.claude/projects/`, `.windsurf/features/`, `.continue/tasks/` | 目录链接 |

### 关键设计原则

**逐文件链接，不整目录链接**：
- 整目录链接会把 `README.md` 也注入工具，污染上下文
- 逐文件链接精确控制哪些文件被载入

**L2 是自动载入层，L3 不自动载入**：
- L2（11个分类索引，≤50行/文件）适合每次对话自动载入
- L3（精炼规范，≤200行/文件）通过 `globs` frontmatter 按需触发
- 所有工具的 rules 目录只映射 L2，不映射 L3

### 移除映射时的检查

`8g` 移除映射时，除了删除链接，还会检查各 IDE 目录中是否有**非链接的意外文件**，并报告给用户（不自动删除）。

### 映射定义的单一数据源

所有映射关系定义在 `gogogo.8.sh` 的 `MAPPINGS` 数组中，通过 `build_mappings()` 函数动态生成。新增工具支持只需在此处添加，不需要修改其他地方。

## AI 体系管理规范（`gogogo.ai.sh`）

### 双重角色

`gogogo.ai.sh` 采用**函数库 + 条件菜单执行**模式：

**角色 1：函数库**（被 `source` 时只加载函数）
- `call_ai_api` / `get_ai_commit_message`（供 `gogogo.git.sh` 使用）
- `sync_kiro_specs`（L0 specs → `.kiro/specs/` 映射）
- `show_ai_status`（显示各层状态）
- `write_l5_log`（写入操作日志）

**角色 2：管理菜单**（仅在以下情况显示）：
```bash
if [[ "${BASH_SOURCE[0]}" == "$0" ]] || [ "${choice:-}" = "ai" ]; then
    run_ai_manager_menu
fi
```

这个判断是**零容忍要求**，不能省略。

### 菜单标准项

| 编号 | 功能 |
|------|------|
| 1 | 初始化/重建所有链接（L1+L2+L0 specs） |
| 2 | 检查 AI 体系状态 |
| 3 | 同步 Kiro specs（L0→.kiro/specs/） |
| 4 | 写入 L5 操作日志 |
| 0 | 返回 |

## Kiro Spec 映射原则

源文件保持统一编号命名：
```
.ai/L0/specs/active/{feature}/
├── 00.spec-01.requirements.md
├── 00.spec-02.design.md
├── 00.spec-03.tasks.md
└── 00.spec-04.decisions.md
```

Kiro 要求固定文件名，通过 symlink 解决：
```
.kiro/specs/{feature}/
├── requirements.md  → symlink
├── design.md        → symlink
├── tasks.md         → symlink
└── decisions.md     → symlink
```

**统一规范 > 工具特殊需求**，特殊需求一律通过 symlink 层解决。

## L5 操作日志规范

```bash
./gogogo.sh ai → 选择 4
```

文件命名：`{YYYY-MM-DD}.{type}-{topic}.md`

| 类型 | 含义 |
|------|------|
| `task` | 任务完成记录 |
| `debug` | 调试过程记录 |
| `decision` | 决策变更记录 |
| `session` | 会话摘要 |

## 禁止事项

| ❌ 禁止 | ✅ 正确 |
|---------|---------|
| 在 `.ai/` 内保留运维入口脚本 | 所有操作通过 `gogogo.sh` |
| 整目录链接到 rules 目录 | 逐文件链接，排除 README.md |
| L3 映射到 rules 目录（自动载入） | L3 只按需读取，不自动载入 |
| 手动执行 `ln -sf` 建立映射 | 通过 `./gogogo.sh 8f` |
| 为兼容工具改源文件命名 | 通过 symlink 层解决 |
