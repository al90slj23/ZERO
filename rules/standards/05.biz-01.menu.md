## 📍 文档定位

本文档定义**侧边栏菜单（B区）**的业务逻辑规范。菜单系统是"路径为王"架构的核心体现——自动扫描文件系统目录结构，与 `manifest_list` 表配置合并，生成完整菜单树。

**关联文档**：
- `02.backend-04.db-manifest` - 页面清单表结构
- `03.frontend-02.admin-layout` - 管理后台布局（B区定义）

---

## 🎯 核心理念

### 文件系统优先

**文件系统是菜单的唯一来源**：
- 只要目录存在，就应该在菜单中显示
- 数据库配置是"增强"，不是"必需"
- 新建目录后无需配置即可看到菜单项

### 数据流

```
文件系统扫描 → manifest_list 配置匹配 → 警告标记 → 缓存 → 前端渲染
```

---

## 🔧 菜单生成逻辑

### 核心算法

```
1. 扫描指定目录下的所有子目录
2. 对每个目录：
   a. 用 path 查询 manifest_list 表
   b. 有记录 → 检查字段完整性
   c. 无记录 → 标记"无数据库记录"
3. 生成警告信息
4. 按 sortOrder 排序（无记录的按目录名排序）
5. 递归处理子目录
6. 缓存结果
```

### 伪代码实现

```javascript
function buildMenuTree(basePath) {
  const dirs = scanDirectories(basePath)
  const menuItems = []
  
  for (const dir of dirs) {
    // 跳过非页面目录
    if (SKIP_DIRS.includes(dir.name)) continue
    
    // 查询数据库配置
    const dbRecord = queryManifest(dir.path)
    
    // 构建菜单项
    const menuItem = {
      key: dir.name,
      path: dir.path,
      folderName: dir.name,                    // 始终保留目录名
      
      // 数据库字段（可能为空）
      shortName: dbRecord?.shortName || null,
      icon: dbRecord?.icon || null,
      color: dbRecord?.color || null,
      sortOrder: dbRecord?.sortOrder ?? null,
      
      // 警告状态
      warnings: checkWarnings(dbRecord, dir.name),
      hasDbRecord: !!dbRecord,
      
      children: buildMenuTree(dir.path)
    }
    
    menuItems.push(menuItem)
  }
  
  // 排序：有 sortOrder 的按数值排，没有的按目录名字母序
  return menuItems.sort((a, b) => {
    if (a.sortOrder !== null && b.sortOrder !== null) {
      return a.sortOrder - b.sortOrder
    }
    if (a.sortOrder !== null) return -1
    if (b.sortOrder !== null) return 1
    return a.key.localeCompare(b.key)
  })
}

// 检查警告
function checkWarnings(dbRecord, folderName) {
  const warnings = []
  
  if (!dbRecord) {
    warnings.push({ type: 'NO_DB_RECORD', message: '数据库中无此记录' })
    return warnings
  }
  
  // 检查必需字段
  if (!dbRecord.shortName) {
    warnings.push({ type: 'MISSING_FIELD', field: 'shortName', message: '缺少显示名称' })
  }
  if (!dbRecord.icon) {
    warnings.push({ type: 'MISSING_FIELD', field: 'icon', message: '缺少图标' })
  }
  if (!dbRecord.color) {
    warnings.push({ type: 'MISSING_FIELD', field: 'color', message: '缺少颜色' })
  }
  if (dbRecord.sortOrder === null || dbRecord.sortOrder === undefined) {
    warnings.push({ type: 'MISSING_FIELD', field: 'sortOrder', message: '缺少排序' })
  }
  
  return warnings
}
```

## 📊 显示规则

### 显示名称

```javascript
// 显示逻辑：有 shortName 用 shortName，没有就用目录名
const displayName = item.shortName || item.folderName
```

### 警告状态

| 状态 | 说明 | 显示效果 |
|------|------|---------|
| `NO_DB_RECORD` | 数据库中无此记录 | 显示目录名 + 警告标记 |
| `MISSING_FIELD` | 有记录但字段不完整 | 显示已有值 + 缺失字段警告 |
| 无警告 | 配置完整 | 正常显示 |

### 无硬编码默认值

```javascript
// ❌ 错误：硬编码默认值掩盖问题
icon: dbRecord?.icon || 'help-circle'
color: dbRecord?.color || '#000000'

// ✅ 正确：没有就是没有，显示警告
icon: dbRecord?.icon || null  // 前端根据 null 显示警告状态
color: dbRecord?.color || null
```

## 🚫 跳过的目录

以下目录不应出现在菜单中：

```javascript
const SKIP_DIRS = [
  'components',    // 组件目录
  'utils',         // 工具函数
  'stores',        // 状态管理
  'router',        // 路由配置
  'api',           // API 封装
  'services',      // 服务层
  'composables',   // 组合式函数
  'types',         // 类型定义
  'styles',        // 样式文件
  'assets',        // 静态资源
  'layouts',       // 布局组件
  'internal',      // 内部模块
  'Scope',         // 作用域组件（大驼峰例外）
  'Shared'         // 共享组件（大驼峰例外）
]
```

## 🎨 前端警告显示

### 警告样式

```css
/* 无数据库记录 */
.menu-item--no-record {
  opacity: 0.7;
  border-left: 3px solid #ff4d4f;  /* 红色警告 */
}

/* 字段不完整 */
.menu-item--incomplete {
  border-left: 3px solid #faad14;  /* 黄色警告 */
}

/* 配置完整 */
.menu-item--complete {
  /* 正常样式 */
}
```

### 警告提示

```javascript
// 渲染警告提示
function renderWarnings(item) {
  if (!item.hasDbRecord) {
    return `⚠️ 数据库中无此记录`
  }
  
  if (item.warnings.length > 0) {
    const missing = item.warnings
      .filter(w => w.type === 'MISSING_FIELD')
      .map(w => w.field)
      .join('、')
    return `⚠️ 缺少字段：${missing}`
  }
  
  return null
}
```

### 显示效果示例

```
✅ 用户管理          （配置完整）
⚠️ settings          （无数据库记录，显示目录名）
⚠️ 权限配置          （缺少字段：icon、color）
```

## 📋 字段使用指南

### 显示名称字段

| 字段 | 长度 | 使用场景 |
|------|------|---------|
| `briefName` | 1-2字 | 顶部导航（一级菜单） |
| `shortName` | 4-6字 | 侧边栏菜单、面包屑 |
| `name` | 完整名称 | 页面标题、详情页 |

### sortOrder 设置建议

```
核心功能：10-50
常用功能：60-100
辅助功能：110+
未配置：-1（自动排最前）
```

使用 10 的倍数，便于后续插入。

## 🔄 缓存机制

### 缓存策略

菜单数据应该缓存，避免每次请求都扫描文件系统：

```javascript
// 缓存键
const CACHE_KEY = 'menu_tree_v1'

// 获取菜单（优先缓存）
function getMenuTree() {
  let cached = cache.get(CACHE_KEY)
  if (cached) return cached
  
  const tree = buildMenuTree(BASE_PATH)
  cache.set(CACHE_KEY, tree, TTL)
  return tree
}
```

### 缓存刷新时机

1. **手动刷新**：管理后台提供刷新按钮
2. **文件变化**：新建/删除目录后
3. **配置变化**：修改 manifest_list 表后
4. **定时刷新**：可选，设置 TTL

## 📝 开发流程

### 新建页面目录

```bash
# 1. 创建目录
mkdir -p pages/admin/users/settings/

# 2. 创建入口文件
touch pages/admin/users/settings/index.vue

# 3. 刷新菜单缓存
# （点击管理后台刷新按钮，或执行缓存清除命令）

# 4. 查看效果
# 新目录应显示在侧边栏最前面（问号图标、黑色）

# 5. 配置数据库（可选）
# 在 manifest_list 表中添加配置

# 6. 再次刷新
# 确认配置生效
```

### 排查菜单不显示

1. 检查目录是否存在
2. 检查目录名是否在 `SKIP_DIRS` 列表中
3. 检查缓存是否过期
4. 检查入口文件是否存在（如 `index.vue`）
5. 清除缓存后重试
