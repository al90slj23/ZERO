# 06.quality-03.error - 错误处理规范

> **文档版本**：v1.0.0
> **创建日期**：2025-12-30

---

## 📍 文档定位

本文档定义**前后端统一的错误处理机制**，涵盖异常捕获、日志记录和用户提示。

---

## 🎯 核心理念

1. **统一处理**：前后端使用一致的错误码和消息格式
2. **用户友好**：错误提示清晰易懂，不暴露技术细节
3. **便于排查**：日志记录完整，便于问题定位

---

## 📊 HTTP 状态码映射

| 状态码 | 含义 | 前端处理 |
|--------|------|---------|
| 400 | 请求参数错误 | 显示错误信息 |
| 401 | 未认证/登录过期 | 跳转登录页 |
| 403 | 无权限 | 显示权限提示 |
| 404 | 资源不存在 | 显示不存在提示 |
| 422 | 验证失败 | 显示字段错误 |
| 500 | 服务器错误 | 显示通用错误 |

## 🖥️ 前端错误处理

### 统一错误处理类

```javascript
class ErrorHandler {
  static handleApiError(error, defaultMessage = '操作失败') {
    console.error('API Error:', error)
    
    if (error.response) {
      const { status, data } = error.response
      
      switch (status) {
        case 400:
          showError(data.message || '请求参数错误')
          break
        case 401:
          showError('未登录或登录已过期')
          redirectToLogin()
          break
        case 403:
          showError('没有权限访问')
          break
        case 404:
          showError('请求的资源不存在')
          break
        case 422:
          this.handleValidationError(data.errors)
          break
        case 500:
          showError('服务器内部错误')
          break
        default:
          showError(data.message || defaultMessage)
      }
    } else if (error.request) {
      showError('网络连接失败，请检查网络设置')
    } else {
      showError(error.message || defaultMessage)
    }
  }

  static handleValidationError(errors) {
    const firstError = Object.values(errors)[0]?.[0]
    if (firstError) {
      showError(firstError)
    }
    return errors
  }
}
```

### 全局错误捕获

```javascript
// 全局错误处理
window.addEventListener('error', (event) => {
  console.error('Global Error:', event.error)
  ErrorHandler.handleUnknownError(event.error)
})

// Promise 未捕获错误
window.addEventListener('unhandledrejection', (event) => {
  console.error('Unhandled Promise Rejection:', event.reason)
  ErrorHandler.handleUnknownError(event.reason)
  event.preventDefault()
})
```

## 🔧 后端错误处理

### 统一响应格式

```json
// 成功响应
{
  "success": true,
  "data": { ... },
  "message": "操作成功"
}

// 错误响应
{
  "success": false,
  "message": "错误描述",
  "errors": { ... }  // 验证错误时
}
```

### 自定义业务异常

```javascript
class BusinessException extends Error {
  constructor(message, code = 0, statusCode = 400) {
    super(message)
    this.code = code
    this.statusCode = statusCode
  }
}

// 使用示例
if (userExists) {
  throw new BusinessException('用户名已存在', 1001)
}
```

## 📝 日志规范

### 日志级别

| 级别 | 使用场景 | 举例 |
|------|---------|------|
| `error` | 错误，需要关注 | 数据库连接失败 |
| `warn` | 警告，异常但不影响功能 | 用户名已存在 |
| `info` | 信息，关键操作记录 | 用户创建成功 |
| `debug` | 调试，开发时使用 | 请求参数详情 |

### 日志内容

```javascript
// 错误日志
logger.error('创建用户失败', {
  error: error.message,
  userData: data,
  stack: error.stack
})

// 警告日志
logger.warn('用户名已存在', {
  username: data.username
})

// 信息日志
logger.info('用户创建成功', {
  userId: user.id
})
```

## 💬 用户提示规范

### 错误提示分类

| 错误类型 | 提示方式 | 举例 |
|---------|---------|------|
| 表单验证错误 | 字段下方红色提示 | "邮箱格式不正确" |
| 操作失败 | 顶部错误消息 | "保存失败，请重试" |
| 网络错误 | 顶部错误消息 | "网络连接失败" |
| 权限错误 | 顶部消息 + 跳转 | "没有权限访问" |
| 系统错误 | 顶部错误消息 | "系统错误，请联系管理员" |

### 提示原则

1. **用户能理解**：避免技术术语
2. **提供解决方案**：告诉用户怎么做
3. **不暴露敏感信息**：生产环境隐藏堆栈

```
❌ "Error: ECONNREFUSED 127.0.0.1:3306"
✅ "服务暂时不可用，请稍后重试"

❌ "Undefined index: user_id"
✅ "数据加载失败，请刷新页面"
```
