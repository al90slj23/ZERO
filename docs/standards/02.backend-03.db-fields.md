# 02.backend-03.db-fields - 数据库字段命名规范

> **文档版本**：v1.0.0
> **创建日期**：2025-12-30

---

## 📍 文档定位

定义数据库字段命名规范（三段式），让字段按业务实体和语义分类自然聚合。

---

## 🎯 字段结构规则

### 基础格式（至少三段，按需扩展）

字段名**至少**由三段组成，当业务需要更细的层级时可扩展为四段、五段甚至更多：

```
基础格式：{表级前缀}_{语义分类}_{字段名}
扩展格式：{表级前缀}_{语义分类}_{子分类}_{字段名}
更深层级：{表级前缀}_{语义分类}_{子分类}_{细分}_{字段名}
```

| 段 | 说明 | 要求 |
|---|------|------|
| **表级前缀** | 所属业务实体 | 如 `base`、`vip`、`order`、`itemsimages` |
| **语义分类** | 字段用途分类 | 必须是单个英文单词 |
| **子分类** | 更细的分类（可选） | 当分类下有多个相关字段时使用 |
| **细分** | 更深层级（可选） | 当子分类下还需细分时使用 |
| **字段名** | 具体字段含义 | 单个英文单词 |

### 举例

```sql
-- 基础三段式
base_core_username           -- 基础-核心-用户名
base_profile_nickname        -- 基础-资料-昵称
base_status_active           -- 基础-状态-激活

-- 扩展四段式（当子分类下有多个字段时）
base_bind_wechat_openid      -- 基础-绑定-微信-OpenID
base_bind_wechat_unionid     -- 基础-绑定-微信-UnionID
order_payment_method_type    -- 订单-支付-方式-类型
itemsimages_image_width      -- 图片-图片-宽度
itemsimages_image_height     -- 图片-图片-高度
streamsinfos_video_codec     -- 流信息-视频-编码
streamsinfos_audio_channels  -- 流信息-音频-声道数

-- 扩展五段式（更深层级）
server_speed_test_time       -- 服务器-速度-测试-时间
server_speed_success_rate    -- 服务器-速度-成功-率
base_bind_wechat_mini_openid -- 基础-绑定-微信-小程序-OpenID
```

### 例外字段（不参与命名规则）

以下字段全系统通用，不加任何前缀与分类：

```sql
id           -- 固定第1位
user_id      -- 固定第2位（如有外键）
created_at   -- 固定倒数第3位
updated_at   -- 固定倒数第2位
deleted_at   -- 固定最后1位
```

**位置规则**：
- `id`、`user_id` 固定在表最前面
- `created_at`、`updated_at`、`deleted_at` 固定在表最后面

## 📋 常用语义分类

### 通用分类

| 分类 | 说明 | 举例字段 |
|------|------|----------|
| `core` | 核心标识 + 安全凭证 | `base_core_username`、`base_core_password` |
| `profile` | 用户自填信息 | `base_profile_nickname`、`base_profile_avatar` |
| `bind` | 绑定信息 | `base_bind_phone`、`base_bind_email` |
| `status` | 状态标识 | `base_status_active`、`base_status_verified` |
| `count` | 计数统计 | `base_count_login`、`base_count_orders` |
| `time` | 时间记录 | `base_time_lastlogin`、`base_time_verified` |

### 业务分类（按需定义）

| 分类 | 说明 | 举例字段 |
|------|------|----------|
| `level` | 等级相关 | `vip_level_current`、`vip_level_expire` |
| `payment` | 支付相关 | `order_payment_method`、`order_payment_status` |
| `shipping` | 物流相关 | `order_shipping_address`、`order_shipping_status` |
| `price` | 价格相关 | `product_price_original`、`product_price_current` |

## 📝 字段注释规范

### 格式

```sql
'序号|中文字段分类|中文字段名|详细说明[|是否显示]'
```

### 规则

| 段 | 说明 | 举例 |
|---|------|------|
| 序号 | 字段在表中的逻辑顺序 | `1`、`2`、`3` |
| 中文字段分类 | 字段所属分类 | `核心`、`资料`、`绑定` |
| 中文字段名 | 用于前端表格列头显示 | `用户名`、`昵称` |
| 详细说明 | 详细描述字段用途，枚举值写为 `value1=说明1, value2=说明2` | `用于登录的唯一标识` |
| 是否显示 | `1`=默认显示，`0`=默认隐藏（可选，默认1） | `1` |

### 举例

```sql
`base_core_username` VARCHAR(100) COMMENT '1|核心|用户名|用于登录的唯一标识|1',
`base_core_password` VARCHAR(255) COMMENT '2|核心|密码|加密存储的登录密码|0',
`base_profile_nickname` VARCHAR(100) COMMENT '3|资料|昵称|用户自定义的显示名称|1',
`base_profile_avatar` VARCHAR(500) COMMENT '4|资料|头像|用户头像图片URL|1',
`base_bind_phone` VARCHAR(20) COMMENT '5|绑定|手机号|已验证的手机号码|1',
`base_status_active` TINYINT COMMENT '6|状态|激活状态|0=未激活, 1=已激活|1',
```

## 🔢 字段排序规范

### 排序原则

按**查看频率**和**修改频率**排序：

```
高查看 + 低修改 → 靠前（如：用户名、昵称）
高查看 + 高修改 → 中间（如：状态、计数）
低查看 + 高修改 → 靠后（如：更新时间）
低查看 + 低修改 → 最后（如：创建时间）
```

### 标准排序模板

```sql
-- 1. 系统字段（固定位置）
id                          -- 固定第1位
user_id                     -- 固定第2位（如有）

-- 2. 核心字段（高查看 + 低修改）
base_core_username
base_core_email

-- 3. 资料字段（高查看 + 中修改）
base_profile_nickname
base_profile_avatar

-- 4. 绑定字段（中查看 + 低修改）
base_bind_phone
base_bind_wechat

-- 5. 状态字段（高查看 + 高修改）
base_status_active
base_status_verified

-- 6. 计数字段（中查看 + 高修改）
base_count_login
base_count_orders

-- 7. 时间字段（低查看 + 高修改）
base_time_lastlogin

-- 8. 系统时间戳（固定位置）
created_at                  -- 固定倒数第3位
updated_at                  -- 固定倒数第2位
deleted_at                  -- 固定最后1位
```

## 🚫 命名优先级原则

**重要程度从高到低**：

1. **语义优先于直译** - 选择最能表达业务含义的词
2. **长期稳定优先** - 字段名应能长期使用，不因实现变化而改变
3. **宁用抽象单词** - 避免组合词，选择更高阶的单词替代
4. **不写实现细节** - 字段名不应暴露存储格式、数据类型等实现细节

### 对比举例

```sql
-- ❌ 错误示例
emergency_contact_phone        -- 复合词，太具体
working_hours_json             -- 暴露实现细节
is_online_visible              -- 旧前缀式

-- ✅ 正确示例
user_contact_emergency         -- 三段式
user_work_schedule             -- 抽象表达
user_visibility_online         -- 三段式
```

## 🚫 禁止的命名方式

| 禁止 | 原因 | 正确做法 |
|------|------|----------|
| 拼音命名 | 不通用 | 使用英文 |
| 复合词 | 如 `emergency_contact` | 用抽象单词或三段式 |
| 暴露实现 | 如 `_json`、`_array` 后缀 | 省略实现细节 |
| 旧前缀式 | 如 `is_`、`num_`、`date_` | 按三段式命名 |
