# 02.backend-02.db-tables - 数据库表命名规范

> **文档版本**：v1.0.0
> **创建日期**：2025-12-30

---

## 📍 文档定位

定义数据库表命名规范，包括通用语义后缀（单数形式）、表注释格式。

---

## 🎯 表命名格式

```
{业务域}_{子域}_{通用语义后缀}_{细分类型}
```

### 通用语义后缀（单数形式）

**规则**：通用语义后缀使用**单数形式**，以区别于普通业务词汇（复数形式）

| 后缀 | 含义 | 使用场景 | 举例 |
|------|------|----------|------|
| `list` | 主表/列表 | 核心业务实体的数据集 | `users_list` |
| `config` | 配置表 | 静态配置项、类型定义 | `users_config_roles` |
| `log` | 日志表 | 事件/操作/变更记录 | `users_log_login` |
| `data` | 扩展数据 | 主表的1:1附属信息 | `users_vip_data` |
| `history` | 历史快照 | 状态变迁记录、版本追溯 | `orders_log_history` |
| `file` | 文件资源 | 附件/上传文件记录 | `products_log_file` |
| `relation` | 关系表 | 实体间的关联映射 | `users_relation_groups` |

### 命名规则

```
通用语义后缀 = 单数（list/config/log/data/history/file/relation）
普通业务词汇 = 复数（users/orders/items/levels/roles...）
```

---

## 📋 组合举例

```sql
-- 主表
users_list                      -- 用户主表
orders_list                     -- 订单主表
products_list                   -- 产品主表

-- 配置表（config + 业务词汇复数）
users_config_roles              -- 角色配置
users_config_levels             -- 等级配置
products_config_types           -- 产品类型配置

-- 日志表（log + 业务词汇）
users_log_login                 -- 登录日志
orders_log_status               -- 订单状态变更日志

-- 扩展数据
users_vip_data                  -- VIP用户扩展数据
users_seller_data               -- 卖家扩展数据

-- 关系表
users_relation_groups           -- 用户-分组关系
products_relation_tags          -- 产品-标签关系
```

### ⚠️ 常见错误

```sql
-- ❌ 错误：通用语义后缀用了复数
users_lists                     -- 应为 list
users_configs_roles             -- 应为 config_roles
users_logs_login                -- 应为 log_login

-- ✅ 正确：通用语义后缀用单数
users_list
users_config_roles
users_log_login
```

## 📝 表注释规范

### 格式

```
中文名称|功能说明
```

### 规则

| 规则 | 说明 | 举例 |
|------|------|------|
| 分隔符 | 统一使用半角 `\|` | `用户主表\|存储用户基础信息` |
| 中文名称 | 简洁明了，不带"表"后缀 | `用户主表` ✅ / `用户主表表` ❌ |
| 功能说明 | 一句话描述核心功能 | `存储用户基础信息和认证信息` |
| 总长度 | 建议 ≤60 字符 | - |

### 举例

```sql
-- ✅ 正确格式
'用户主表|存储用户基础信息和认证信息'
'角色配置|定义系统中的用户角色及权限'
'登录日志|记录用户登录行为和设备信息'

-- ❌ 错误格式
'用户主表：存储用户基础信息'           -- 分隔符错误，应用 |
'用户主表表|存储用户基础信息'          -- 名称冗余
'存储用户基础信息和认证信息'           -- 缺少中文名称
```

## 🏗️ 主表与扩展表模式

### 模式定义

```
主表（Base Table）：
- 存储通用字段
- 所有实体共有的属性
- 命名后缀：_list

扩展表（Extension Table）：
- 存储专属字段
- 特定类型/角色的属性
- 命名后缀：_data
```

### 举例

```sql
-- 主表：存储所有用户的通用信息
users_list (
    id, username, email, phone, password,
    nickname, avatar, status,
    created_at, updated_at
)

-- 扩展表1：VIP用户专属数据
users_vip_data (
    id, user_id,
    level, discount_rate, points,
    created_at, updated_at
)

-- 扩展表2：卖家专属数据
users_seller_data (
    id, user_id,
    shop_name, rating, total_sales,
    created_at, updated_at
)
```

### 身份叠加设计

一个用户可以同时拥有多个角色：

```sql
-- 用户A：普通用户
users_list: id=100

-- 用户B：普通用户 + VIP
users_list: id=200
users_vip_data: user_id=200

-- 用户C：普通用户 + VIP + 卖家
users_list: id=300
users_vip_data: user_id=300
users_seller_data: user_id=300
```

## 🔄 路径映射

### 文件夹路径 → 数据库表

```
文件夹路径：pages/admin/users/config/levels/
数据库表：admin_users_config_levels

文件夹路径：pages/admin/orders/list/
数据库表：admin_orders_list
```

### 映射规则

1. 用下划线连接所有层级目录
2. 最后一级如果是 `list` 保持单数
