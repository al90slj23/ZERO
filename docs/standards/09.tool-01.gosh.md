## 📍 文档定位

本文档定义 **go.sh 统一入口脚本**的设计规范。go.sh 是项目的统一命令入口，通过数字选项快速执行常用操作。

---

## 🎯 核心理念

### 为什么需要 go.sh

1. **统一入口**：一个命令搞定所有常用操作
2. **降低记忆成本**：不用记复杂命令，数字选择即可
3. **模块化扩展**：按需添加子脚本，主入口不变
4. **团队协作**：新成员快速上手

### 设计原则

1. **简单直观**：数字选项，一目了然
2. **模块化**：每个功能独立子脚本
3. **可扩展**：新功能只需添加 `go.N.sh`
4. **自文档化**：菜单即文档

## 📁 文件结构

```
project/
├── go.sh          # 主入口（必需）
├── go.lib.sh      # 通用库（必需）
├── go.0.sh        # 选项 0: 本地开发
├── go.1.sh        # 选项 1: 部署（默认）
├── go.2.sh        # 选项 2: 检查状态
├── go.3.sh        # 选项 3: 清缓存
├── go.4.sh        # 选项 4: 测试
├── go.5.sh        # 选项 5: 构建
└── ...            # 按需扩展
```

---

## 📝 文件职责

### go.sh（主入口）

- 加载库文件
- 显示菜单
- 接收用户选择
- 调度子脚本

### go.lib.sh（通用库）

- 颜色定义
- 工具函数（检查、输出、确认等）
- 服务管理函数

### go.N.sh（子脚本）

- 单一职责
- 可独立执行
- 依赖 go.lib.sh

## 🔢 选项编号规范

### 推荐编号

| 编号 | 用途 | 说明 |
|------|------|------|
| 0 | 本地开发 | 启动开发服务器 |
| 1 | 部署 | 推送 GitHub + 部署到服务器（默认选项） |
| 2 | 检查状态 | 检查服务状态 |
| 3 | 清缓存 | 清除各类缓存 |
| 4 | 测试 | 运行测试 |
| 5 | 构建 | 构建生产版本 |
| 6-9 | 扩展 | 项目特定功能 |

### 编号原则

- **1 是默认**：部署是最常用的操作，直接回车或 10 秒超时自动执行
- **0 是本地开发**：开发环境启动放在 0
- **相关功能相邻**：如 1=部署，2=检查状态
- **特殊功能靠后**：不常用的放 6-9

### 颜色定义

```bash
RED='\033[0;31m'      # 错误
GREEN='\033[0;32m'    # 成功
YELLOW='\033[1;33m'   # 警告
BLUE='\033[0;34m'     # 信息
CYAN='\033[1;36m'     # 步骤
NC='\033[0m'          # 重置
```

### 输出函数


## 🚀 使用方式

### 交互式

```bash
./go.sh
# 显示菜单，等待用户选择
```

### 直接执行

```bash
./go.sh 1    # 直接执行选项 1
./go.sh 2    # 直接执行选项 2
```

### 超时自动选择

```bash
# 10秒无输入自动选择默认选项（通常是 1）
read -t 10 -p "请选择: " choice
```

## 💡 最佳实践

### 1. 保持简单

```bash
# ✅ 好：简单直接
./go.sh 1

# ❌ 不好：复杂参数
./go.sh --mode=dev --port=3000 --verbose
```

### 2. 自动检测环境

```bash
# 根据项目类型自动调整
if [ -f "package.json" ]; then
    npm run dev
elif [ -f "artisan" ]; then
    php artisan serve
fi
```

### 3. 错误处理

```bash
# 命令失败时提示
if ! npm run build; then
    error "构建失败"
    exit 1
fi
```
