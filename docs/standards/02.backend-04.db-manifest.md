## 📍 文档定位

本文档定义**页面清单表（manifest）**的设计规范。这是"路径为王"架构的核心数据表，存储所有页面/功能模块的配置信息。

**关联文档**：
- `03.frontend-02.admin-layout` - 管理后台布局（B区使用此表）
- `05.biz-01.menu` - 侧边栏菜单规范（菜单生成逻辑）

---

## 🎯 核心理念

### 单一数据源

**页面清单表是系统的唯一配置数据源**：
- 所有页面的路由、菜单、权限信息都从此表获取
- 文件系统变化必须同步到此表
- 前端菜单、后端路由、权限控制都依赖此表

### 表命名

```
{系统前缀}_manifest_list
```

举例：
- `yys_manifest_list` - YYS系统的页面清单
- `admin_manifest_list` - 管理后台的页面清单
- `app_manifest_list` - 应用的页面清单

## 📋 核心字段

### 必需字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 主键 |
| `path` | VARCHAR(500) | 文件夹路径（唯一主体） |
| `url` | VARCHAR(200) | 访问URL |
| `route` | VARCHAR(100) | 路由名称 |
| `name` | VARCHAR(100) | 完整名称 |
| `shortName` | VARCHAR(50) | 简短名称（菜单显示） |
| `status` | VARCHAR(20) | 状态 |
| `sortOrder` | INT | 排序顺序 |
| `created_at` | TIMESTAMP | 创建时间 |
| `updated_at` | TIMESTAMP | 更新时间 |

### 可选字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `briefName` | VARCHAR(30) | 极简名称 |
| `info` | TEXT | 详细说明 |
| `shortInfo` | VARCHAR(200) | 简短说明 |
| `helpText` | TEXT | 帮助文本 |
| `icon` | VARCHAR(50) | 图标名称 |
| `color` | VARCHAR(20) | 主题颜色 |
| `vuePageComponent` | VARCHAR(500) | 页面组件路径 |
| `mappedPath` | VARCHAR(500) | 映射路径（快捷入口） |
| `supportingFiles` | TEXT | 配套文件列表 |
| `metadata` | JSON | 扩展元数据 |

## 🔄 路径映射关系

### path 字段是唯一主体

```
path: /resources/js/views/admin/users/list/
        ↓ 自动推导
url: /admin/users/list
route: admin_users_list
数据库表: admin_users_list
类名: AdminUsersList
权限: admin.users.list
```

### 字段生成规则

| 字段 | 生成规则 | 举例 |
|------|---------|------|
| `url` | 移除 `/resources/js/views` 前缀 | `/admin/users/list` |
| `route` | 路径用下划线连接 | `admin_users_list` |
| `shortName` | 默认使用文件夹名 | `list` |

## 📊 状态定义

| 状态值 | 说明 |
|--------|------|
| `active` | 活跃（正常使用） |
| `inactive` | 停用 |
| `development` | 开发中 |
| `core_system` | 核心系统（不可删除） |
| `basic_framework` | 基础框架 |

---

## 🔧 Fallback 策略

当数据库无配置时，使用简单二元规则：

| 字段 | Fallback 值 | 说明 |
|------|-------------|------|
| `shortName` | 文件夹名 | 直接显示目录名 |
| `icon` | `help-circle` | 问号图标，提示需配置 |
| `color` | `#000000` | 纯黑色 |
| `sortOrder` | `-1` | 排在最前面，提示需配置 |
| `status` | `active` | 默认活跃 |

**设计原则**：Fallback 值应该能快速暴露"未配置"问题，而不是掩盖它。

## 📝 建表示例

```sql
CREATE TABLE `xxx_manifest_list` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT COMMENT '1|系统|主键ID|自增主键|0',
  `path` varchar(500) NOT NULL COMMENT '2|核心|文件路径|文件夹路径，唯一主体|1',
  `url` varchar(200) NOT NULL COMMENT '3|核心|访问URL|页面访问地址|1',
  `route` varchar(100) NOT NULL COMMENT '4|核心|路由名称|前端路由标识|1',
  `name` varchar(100) NOT NULL COMMENT '5|显示|完整名称|页面完整名称|1',
  `shortName` varchar(50) NOT NULL COMMENT '6|显示|简短名称|菜单显示名称|1',
  `briefName` varchar(30) DEFAULT NULL COMMENT '7|显示|极简名称|极简显示|0',
  `info` text COMMENT '8|说明|详细说明|页面详细描述|0',
  `shortInfo` varchar(200) DEFAULT NULL COMMENT '9|说明|简短说明|简短描述|0',
  `helpText` text COMMENT '10|说明|帮助文本|使用帮助|0',
  `icon` varchar(50) DEFAULT 'help-circle' COMMENT '11|显示|图标|菜单图标名称|1',
  `color` varchar(20) DEFAULT '#000000' COMMENT '12|显示|颜色|主题颜色|0',
  `sortOrder` int NOT NULL DEFAULT '-1' COMMENT '13|排序|排序顺序|数值越小越靠前|1',
  `status` varchar(20) NOT NULL DEFAULT 'active' COMMENT '14|状态|状态|active=活跃, inactive=停用, development=开发中|1',
  `vuePageComponent` varchar(500) DEFAULT NULL COMMENT '15|技术|组件路径|Vue页面组件路径|0',
  `mappedPath` varchar(500) DEFAULT NULL COMMENT '16|技术|映射路径|快捷入口映射|0',
  `supportingFiles` text COMMENT '17|技术|配套文件|相关文件列表|0',
  `metadata` json DEFAULT NULL COMMENT '18|扩展|元数据|JSON扩展数据|0',
  `created_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP COMMENT '19|系统|创建时间|记录创建时间|0',
  `updated_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '20|系统|更新时间|记录更新时间|0',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_path` (`path`),
  UNIQUE KEY `uk_route` (`route`),
  KEY `idx_status` (`status`),
  KEY `idx_sort` (`sortOrder`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='页面清单表|存储所有页面的配置信息';
```

## 🔄 同步机制

### 文件系统 → 数据库

当文件系统发生变化时，必须同步到数据库：

```bash
# 同步命令（按项目实现）
php artisan manifest:sync      # 扫描文件系统，同步到数据库
php artisan manifest:validate  # 验证数据库与文件系统一致性
php artisan manifest:fix       # 自动修复不一致问题
```

### 同步规则

1. **新增目录** → 插入记录（使用 Fallback 值）
2. **删除目录** → 标记为 `inactive`（不物理删除）
3. **重命名目录** → 更新 `path` 字段

## 🎯 使用场景

### 1. 菜单生成

```javascript
// 前端根据 manifest 数据生成菜单
const menuItems = manifestData
  .filter(item => item.status === 'active')
  .sort((a, b) => a.sortOrder - b.sortOrder)
  .map(item => ({
    label: item.shortName,
    icon: item.icon,
    path: item.url
  }))
```

### 2. 路由注册

```javascript
// 动态注册路由
manifestData.forEach(item => {
  router.addRoute({
    path: item.url,
    name: item.route,
    component: () => import(item.vuePageComponent)
  })
})
```

### 3. 权限控制

```php
// 后端权限检查
$permission = str_replace('/', '.', trim($path, '/'));
if (!$user->hasPermission($permission)) {
    abort(403);
}
```
