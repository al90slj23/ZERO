# 02.backend-02.db-tables - 数据库表命名规范

> **文档版本**：v1.0.0
> **创建日期**：2025-12-30

---

## 📍 文档定位

定义数据库表命名规范，包括通用语义后缀（单数形式）、表注释格式。

---

## 🎯 表命名格式

```
{业务域}_{子域}_{通用语义后缀}_{细分类型}
```

### 通用语义后缀（单数形式）

**规则**：通用语义后缀使用**单数形式**，以区别于普通业务词汇（复数形式）

| 后缀 | 含义 | 使用场景 | 举例 |
|------|------|----------|------|
| `list` | 主表/列表 | 核心业务实体的数据集 | `users_list` |
| `config` | 配置表 | 静态配置项、类型定义 | `users_config_roles` |
| `log` | 日志表 | 事件/操作/变更记录 | `users_log_login` |
| `data` | 扩展数据 | 主表的1:1附属信息 | `users_vip_data` |
| `history` | 历史快照 | 状态变迁记录、版本追溯 | `orders_log_history` |
| `file` | 文件资源 | 附件/上传文件记录 | `products_log_file` |
| `relation` | 关系表 | 实体间的关联映射 | `users_relation_groups` |

### 命名规则

```
通用语义后缀 = 单数（list/config/log/data/history/file/relation）
普通业务词汇 = 复数（users/orders/items/levels/roles...）
```

---

## 📋 组合举例

```sql
-- 主表
users_list                      -- 用户主表
orders_list                     -- 订单主表
products_list                   -- 产品主表

-- 配置表（config + 业务词汇复数）
users_config_roles              -- 角色配置
users_config_levels             -- 等级配置
products_config_types           -- 产品类型配置

-- 日志表（log + 业务词汇）
users_log_login                 -- 登录日志
orders_log_status               -- 订单状态变更日志

-- 扩展数据
users_vip_data                  -- VIP用户扩展数据
users_seller_data               -- 卖家扩展数据

-- 关系表
users_relation_groups           -- 用户-分组关系
products_relation_tags          -- 产品-标签关系
```

### ⚠️ 常见错误

```sql
-- ❌ 错误：通用语义后缀用了复数
users_lists                     -- 应为 list
users_configs_roles             -- 应为 config_roles
users_logs_login                -- 应为 log_login

-- ✅ 正确：通用语义后缀用单数
users_list
users_config_roles
users_log_login
```

## 📝 表注释规范

### 格式

```
中文名称|功能说明
```

### 规则

| 规则 | 说明 | 举例 |
|------|------|------|
| 分隔符 | 统一使用半角 `\|` | `用户主表\|存储用户基础信息` |
| 中文名称 | 简洁明了，不带"表"后缀 | `用户主表` ✅ / `用户主表表` ❌ |
| 功能说明 | 一句话描述核心功能 | `存储用户基础信息和认证信息` |
| 总长度 | 建议 ≤60 字符 | - |

### 举例

```sql
-- ✅ 正确格式
'用户主表|存储用户基础信息和认证信息'
'角色配置|定义系统中的用户角色及权限'
'登录日志|记录用户登录行为和设备信息'

-- ❌ 错误格式
'用户主表：存储用户基础信息'           -- 分隔符错误，应用 |
'用户主表表|存储用户基础信息'          -- 名称冗余
'存储用户基础信息和认证信息'           -- 缺少中文名称
```

## 🏗️ 主表与扩展表模式

### 模式定义

```
主表（Base Table）：
- 存储通用字段
- 所有实体共有的属性
- 命名后缀：_list

扩展表（Extension Table）：
- 存储专属字段
- 特定类型/角色的属性
- 命名后缀：_data
```

### 举例

```sql
-- 主表：存储所有用户的通用信息
users_list (
    id, username, email, phone, password,
    nickname, avatar, status,
    created_at, updated_at
)

-- 扩展表1：VIP用户专属数据
users_vip_data (
    id, user_id,
    level, discount_rate, points,
    created_at, updated_at
)

-- 扩展表2：卖家专属数据
users_seller_data (
    id, user_id,
    shop_name, rating, total_sales,
    created_at, updated_at
)
```

### 身份叠加设计

一个用户可以同时拥有多个角色：

```sql
-- 用户A：普通用户
users_list: id=100

-- 用户B：普通用户 + VIP
users_list: id=200
users_vip_data: user_id=200

-- 用户C：普通用户 + VIP + 卖家
users_list: id=300
users_vip_data: user_id=300
users_seller_data: user_id=300
```

## 🔑 Key-Value 配置表规范

### 表结构类型

数据库表按数据存储方向分为两种类型：

| 类型 | 别名 | 数据方向 | 主键类型 | 典型场景 |
|------|------|----------|----------|----------|
| **横向表** | 实体表 | 一行多列 | 自增 ID | 用户、订单、商品 |
| **纵向表** | KV 表 | 多行键值对 | 自然主键（Key） | 系统配置、站点信息 |

### 纵向表（Key-Value 表）设计规范

#### 列顺序（Column Order）

纵向表的列物理顺序**必须**遵循以下规范：

```
配置键 → 配置值 → 名称 → 说明 → 显示顺序 → [其他字段] → 系统字段
```

| 序号 | 字段 | 命名规范 | 说明 |
|------|------|----------|------|
| 1 | 配置键 | `{前缀}_core_key` | 主键，唯一标识 |
| 2 | 配置值 | `{前缀}_core_value` | 配置项的值 |
| 3 | 名称 | `{前缀}_display_label` 或 `{前缀}_core_label` | 中文名称，便于理解 |
| 4 | 说明 | `{前缀}_info_hint` | 用途说明 |
| 5 | 显示顺序 | `{前缀}_sort_order` | 前端显示排序权重 |
| 6+ | 其他 | 按需添加 | 如分组、状态等 |
| 末尾 | 系统字段 | `updated_at` 等 | 时间戳 |

#### 主键设计

**纵向表不需要自增 ID 主键**，配置键本身就是自然主键：

```sql
-- ✅ 正确：使用配置键作为主键
CREATE TABLE cmd_cfghub_settings (
    settings_core_key VARCHAR(50) NOT NULL PRIMARY KEY,
    settings_core_value TEXT,
    settings_display_label VARCHAR(100),
    settings_info_hint VARCHAR(200),
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- ❌ 错误：不需要自增 ID
CREATE TABLE cmd_cfghub_settings (
    id INT AUTO_INCREMENT PRIMARY KEY,  -- 多余
    settings_core_key VARCHAR(50) NOT NULL UNIQUE,
    ...
);
```

#### 完整示例

```sql
CREATE TABLE cmd_cfghub_settings (
    settings_core_key VARCHAR(50) NOT NULL 
        COMMENT '1|核心|配置键|配置项唯一标识|1',
    settings_core_value TEXT 
        COMMENT '2|核心|配置值|配置项的值|1',
    settings_display_label VARCHAR(100) DEFAULT NULL 
        COMMENT '3|显示|名称|配置项中文名称|1',
    settings_info_hint VARCHAR(200) DEFAULT NULL 
        COMMENT '4|信息|说明|配置项用途说明|1',
    settings_sort_order INT DEFAULT 0 
        COMMENT '5|排序|显示顺序|配置项排序权重|1',
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP 
        COMMENT '6|系统|更新时间|记录更新时间|0',
    PRIMARY KEY (settings_core_key)
) COMMENT='系统设置|存储全局系统配置';
```

#### 适用场景

| 场景 | 表名示例 | 说明 |
|------|----------|------|
| 系统配置 | `cmd_cfghub_settings` | 全局系统参数 |
| 站点信息 | `cmd_cfghub_msrlinfo` | 站点名称、品牌等 |
| 功能开关 | `cmd_cfghub_features` | 功能启用/禁用 |
| 环境变量 | `cmd_cfghub_env` | 环境相关配置 |

## 🔄 路径映射

### 文件夹路径 → 数据库表

```
文件夹路径：pages/admin/users/config/levels/
数据库表：admin_users_config_levels

文件夹路径：pages/admin/orders/list/
数据库表：admin_orders_list
```

### 映射规则

1. 用下划线连接所有层级目录
2. 最后一级如果是 `list` 保持单数
