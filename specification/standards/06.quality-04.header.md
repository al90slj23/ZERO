# 06.quality-04.header - 文件头注释规范

> **文档版本**：v1.0.0
> **创建日期**：2025-12-30

---

## 📍 文档定位

本文档定义**文件头注释的模板与规范**。核心理念是"文件自包含文档化"——在每个文件开头用详细注释完整记录文件的逻辑、思路、框架、结构等关键信息。

---

## 🎯 核心优势

1. **AI 开发友好**：AI 读取文件时立即获得完整设计思路
2. **文档代码强一致**：文档与代码在同一文件，修改时强制同步更新
3. **高效检索维护**：无需跳转多个文件即可理解功能全貌

---

## 📝 标准注释模板

### JavaScript / TypeScript 文件

```javascript
/**
 * ================================================================
 * 文件名: [完整文件名.扩展名]
 * 创建时间: YYYY-MM-DD
 * 更新时间: YYYY-MM-DD
 * ================================================================
 *
 * 【文件职责】
 * [1-3句话简述文件的核心职责和主要功能]
 *
 * 【核心架构】
 * 1. [核心架构点1]
 * 2. [核心架构点2]
 * 3. [核心架构点3]
 *
 * 【主要函数】
 * - functionName1(): 函数1的作用说明
 * - functionName2(): 函数2的作用说明
 *
 * 【依赖关系】
 * - 内部模块: @/utils/xxx
 * - 外部API: /api/v1/xxx
 *
 * 【使用方法】
 * ```javascript
 * import { funcName } from '@/utils/fileName'
 * const result = await funcName(params)
 * ```
 *
 * 【注意事项】
 * ⚠️ [重要的约束条件]
 *
 * 【更新日志】
 * - YYYY-MM-DD: [更新说明]
 *
 * ================================================================
 */
```

### 后端文件（PHP/Python/Java等）

```php
<?php
/**
 * ================================================================
 * 文件名: [完整文件名]
 * 创建时间: YYYY-MM-DD
 * ================================================================
 *
 * 【文件职责】
 * [简述控制器/模型/服务的主要功能]
 *
 * 【业务逻辑】
 * [详细说明业务处理流程和规则]
 *
 * 【数据库交互】
 * - 涉及的数据表: table_name
 * - 主要查询逻辑: [说明]
 *
 * 【API接口】
 * - GET /api/path: [功能说明]
 * - POST /api/path: [功能说明]
 *
 * 【主要方法】
 * - methodName1(): [方法说明]
 *
 * ================================================================
 */
```

### 配置文件（YAML/JSON）

```yaml

# 创建时间: YYYY-MM-DD

#

# - section2: [配置节说明]
#
# 【使用规范】

# - 注意事项和约束条件

```

## 📋 必需字段

### 基础信息区（强制）

| 字段 | 说明 | 举例 |
|------|------|------|
| 文件名 | 完整文件名，包含扩展名 | `UsersList.logic.ts` |
| 创建时间 | YYYY-MM-DD 格式 | `2025-01-20` |
| 更新时间 | YYYY-MM-DD 格式 | `2025-01-22` |

### 功能说明区（强制）

| 字段 | 说明 |
|------|------|
| 【文件职责】 | 1-3 句话概括文件的核心职责 |
| 【核心架构】 | 列举核心架构要点 |
| 【主要函数】 | 列出文件中的核心函数及其作用 |
| 【依赖关系】 | 详细列出所有依赖 |

### 可选字段

| 字段 | 适用场景 |
|------|---------|
| 【使用方法】 | 需要被其他模块调用的文件 |
| 【数据流】 | 数据处理类文件 |
| 【性能优化】 | 性能敏感的文件 |
| 【注意事项】 | 有特殊约束的文件 |
| 【更新日志】 | 所有文件（推荐） |

---

## 🔄 同步更新规则

- 修改代码时，**必须**同步更新文件头注释
- 新增函数时，**必须**在【主要函数】中添加说明
- 修改依赖时，**必须**更新【依赖关系】
- 重大修改时，**必须**在【更新日志】中记录

## 💡 最佳实践

### 文件职责描述

```
✅ 好的示例：
管理后台用户列表页面逻辑层
负责用户数据的增删改查、批量操作、导入导出
实现"文件系统双向检验 + 数据库配置驱动"的数据管理逻辑

❌ 不好的示例：
用户管理
用于管理用户
```

### 核心架构描述

```
✅ 好的示例：
1. 双向检验：文件系统 ↔ 数据库配置
2. 四种状态识别：正常、配置缺失、路径不存在、信息冲突
3. 智能排序：基于status和sortOrder的优先级排序

❌ 不好的示例：
1. 读取数据
2. 处理数据
3. 返回结果
```
