## 📍 文档定位

本文档定义 **Git 提交信息格式、分支管理流程**。统一的提交规范能提升团队协作效率，保持清晰的版本历史。

---

## 📝 Commit Message 格式

### 基本格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

### 提交类型（Type）

| 类型 | 说明 | 举例 |
|------|------|------|
| `feat` | 新功能 | `feat: 添加用户管理功能` |
| `fix` | 修复 Bug | `fix: 修复登录页面样式问题` |
| `docs` | 文档变更 | `docs: 更新 API 文档` |
| `style` | 代码格式调整 | `style: 调整代码缩进` |
| `refactor` | 代码重构 | `refactor: 重构用户服务层` |
| `perf` | 性能优化 | `perf: 优化列表查询性能` |
| `test` | 测试相关 | `test: 添加用户管理测试用例` |
| `build` | 构建系统 | `build: 升级构建工具` |
| `ci` | CI/CD 配置 | `ci: 添加自动部署配置` |
| `chore` | 其他杂项 | `chore: 更新依赖包版本` |
| `revert` | 回滚提交 | `revert: 回滚用户管理功能` |

### 影响范围（Scope）

常用 Scope：`user`、`auth`、`config`、`api`、`ui`、`db`、`deps`

```
feat(user): 添加用户列表页面
fix(auth): 修复登录验证逻辑
```

### 简短描述（Subject）规则

- 使用祈使句，现在时态
- 首字母小写
- 结尾不加句号
- 不超过 50 个字符

## 📋 提交示例

### 新功能

```
feat(user): 添加用户批量上传功能

实现了用户的批量上传功能：
- 支持 Excel 文件上传
- 自动解析文件内容
- 批量创建用户记录

Closes #234
```

### 修复 Bug

```
fix(auth): 修复登录 token 过期后未跳转登录页

问题：token 过期后，用户仍然可以访问页面

解决方案：
- 在拦截器中检测 401 状态码
- 清除本地 token
- 跳转到登录页面

Fixes #345
```

### 代码重构

```
refactor(user): 重构用户服务层

将用户相关的业务逻辑从控制器中提取到服务层：
- 创建 UserService 类
- 封装用户 CRUD 操作
- 统一错误处理逻辑
```

## 🌿 分支管理规范

### 分支命名

| 分支类型 | 命名格式 | 举例 |
|---------|---------|------|
| 主分支 | `main` | `main` |
| 开发分支 | `develop` | `develop` |
| 功能分支 | `feature/<功能名>` | `feature/user-management` |
| 修复分支 | `fix/<问题描述>` | `fix/login-error` |
| 发布分支 | `release/<版本号>` | `release/v1.2.0` |
| 热修复分支 | `hotfix/<问题描述>` | `hotfix/critical-bug` |

### 分支工作流

```
main (生产环境)
  ↑
  └─ release/v1.2.0 (预发布)
       ↑
       └─ develop (开发环境)
            ↑
            ├─ feature/user-management
            └─ fix/login-error
```

### 分支操作流程

```bash
# 创建功能分支
git checkout develop
git pull origin develop
git checkout -b feature/user-management

# 开发和提交
git add .
git commit -m "feat(user): 添加用户列表页面"

# 合并到 develop
git checkout develop
git merge feature/user-management
git push origin develop
git branch -d feature/user-management
```

## 🔍 代码审查要点

### 功能性
- [ ] 功能是否正确实现
- [ ] 是否有边界情况未处理
- [ ] 错误处理是否完善

### 代码质量
- [ ] 代码是否清晰易懂
- [ ] 是否遵循项目规范
- [ ] 命名是否合理

### 性能
- [ ] 是否有性能问题
- [ ] 数据库查询是否优化

### 安全性
- [ ] 是否有安全漏洞
- [ ] 输入验证是否完善
